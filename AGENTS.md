# CoFlow project conventions

- Preserve the agreed Next.js + Go architecture. Business identity and permissions belong in Go.
- The current project version is recorded in `VERSION`. Do not bump versions or create release tags automatically. Change versions only when the user explicitly requests a version update.
- Keep package metadata, lockfile records, Go version constant, OpenAPI, README and CHANGELOG consistent with `VERSION`. `npm run version:check` only checks and must not modify versions.
- Record subsequent user-facing changes under `Unreleased` in `CHANGELOG.md` until the user requests a release/version change.
- Default to local development and isolated testing. Releases/tags and deployments are separate actions, each requiring an explicit user request; a release does not authorize updating private servers or GitHub Pages. Do not add automatic release or deployment triggers.
- Treat `skills/coflow-report/SKILL.md` and `docs/openapi.yaml` as canonical. The public download copies are generated by `scripts/sync-agent-assets.mjs`.
- Team mode uses PostgreSQL-backed accounts, invitations and personal Agent Tokens; explicit COFLOW_DEMO=true remains a separate local demo. Keep those modes and their data boundaries distinct.

- README language: `README.md` is English by default, with a Simplified Chinese translation in `README.zh-CN.md`. Keep content, version displays, and language-switch links in sync when updating either file.

- UI localization: English (`en`) is the default, with Simplified Chinese (`zh-CN`). Use `useI18n` and the message catalog for interface copy; localize dates/counts without translating user-authored reports, names, comments or category data. Account language preferences belong in Go/PostgreSQL; demo preferences remain browser-local. See `docs/I18N.md`.

- UI design language: concise, direct, and focused on information. Prefer one clear prompt/action, remove duplicate labels and explanations, use restrained motion and spacing to establish hierarchy. Tabs should group distinct tasks; do not add read-only account tabs that repeat menu, team, or language information.
- Simple preferences such as language belong directly in the account menu. Language opens a compact popover with clickable choices, not a native select or settings dialog. Apply and persist selections immediately without a Save button.

- This is a public open-source repository. Keep real team data, account/session/token material, database dumps, backup files and local QA outputs out of Git and external uploads. Use isolated disposable test schemas and synthetic identities. Only reviewed synthetic screenshots on the docs/design allowlist may be tracked; verify staged content before committing or pushing. Never rewrite published history without explicit user authorization.

- GitHub Pages is a public, offline demo using synthetic team data only. It is separate from the owner’s purchased server, which is for private/self-use real teams, not a public GitHub demo backend. Never connect the Pages build to real APIs, accounts, credentials or databases.

- Documentation and GitHub maintenance: follow `docs/MAINTENANCE.md` and `docs/wiki-map.json`. Repository docs and canonical protocols are the source; keep README/Wiki language pairs aligned, track Projects acceptance separately from releases, and report local versus remote sync status accurately. Run `npm run docs:check` for documentation changes; checks never authorize publishing, changing project status, releases or deployments.
