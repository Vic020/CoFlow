# CoFlow project conventions

- Preserve the agreed Next.js + Go architecture. Business identity and permissions belong in Go.
- The current project version is recorded in `VERSION`. Do not bump versions or create release tags automatically. Change versions only when the user explicitly requests a version update.
- Keep package metadata, lockfile records, Go version constant, OpenAPI, README and CHANGELOG consistent with `VERSION`. `npm run version:check` only checks and must not modify versions.
- Record subsequent user-facing changes under `Unreleased` in `CHANGELOG.md` until the user requests a release/version change.
- Treat `skills/coflow-report/SKILL.md` and `docs/openapi.yaml` as canonical. The public download copies are generated by `scripts/sync-agent-assets.mjs`.
- The current application is an explicit local demo. Do not claim production login, invitation or personal Token support until those features are implemented.
