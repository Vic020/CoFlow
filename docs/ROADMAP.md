# CoFlow 版本工作计划

更新：2026-11-11（Asia/Shanghai）。当前版本为 **0.5.3**，包含 Timeline、Todo、Calendar、公共工作范围与 AI 助手首版；Context 首版已实现，其余模型协议、外部写工具及 0.6 范围继续规划。0.4.1 补齐增量接续、Todo 验收与模型列表；真实账号及容量专项仍需独立验收。后续开发变化记录到 CHANGELOG 的 Unreleased。

## 产品主线

**Todo 管行动，Calendar 管时间，Timeline 管进展与交付，AI 助手通过对话串联操作，Context 沉淀值得记住的团队上下文，数据统计帮助团队回顾推进与交付。**

各模块共用团队、项目、领域、成员及权限体系。Todo 完成、调整排期和 Agent 上报可以相互关联，避免同一项工作在多个页面重复维护。

| 版本 | 重点 | 用户获得的能力 |
| --- | --- | --- |
| 0.1 | 进展与协作 | 浏览简报、评论、交付链接，整理项目与领域 |
| 0.2 | 多人、多 Agent 协同交付 | 安排工作、管理状态，让人与 Agent 共同维护待办 |
| 0.3 | 上报日历与排期 | 默认按日期查看真实上报与成果，并在日历／甘特中安排任务、阶段、Big Day 和版本节点 |
| 0.4 | AI 助手 | 通过对话串联各模块；团队共用与个人 API 配置，适配 DeepSeek、GLM、OpenAI／Codex 等服务 |
| 0.5 | Context 知识库 | 从简报、看板与日历沉淀重点、决策和约束，为团队与 AI 提供可追溯的长期上下文 |
| 0.6 | 数据统计 | 按团队、项目、领域、成员与 Agent 来源查看进展、任务流转及交付趋势，回溯原始记录 |

不预设发布日期，按验收结果推进。

### 页面与交互

- 项目、领域和成员放在顶导公共工作范围，跨 Timeline／Todo／Calendar 保持一致；页面保留搜索、新建及模块专属筛选。
- 支持按项目、领域、负责人筛选，以及“全部／与我相关／待我处理”快捷范围；提供重置。
- 每列展示名称、卡片数量及新增入口。卡片突出标题、负责人、项目／领域与截止日期；详情使用居中阅读弹窗，双击字段或悬停末尾铅笔原位编辑，保存后恢复阅读。
- 桌面支持卡片跨列拖拽、列内排序、列顺序拖拽；手机支持横向查看看板，并通过菜单移动卡片和调整顺序。

### 自定义列

列代表工作的推进阶段，项目与领域继续用于分类，彼此独立。

- 默认列：**待办 → 进行中 → 待确认 → 已完成**。
- 团队可新建、重命名、排序和归档列，自定义每列容纳的工作阶段；列可标记为“未完成／已完成”，便于统计及后续排期。
- 每张卡片只属于一列，可关联一个项目和多个领域。
- 含卡片的列归档前，必须选择卡片迁移目标；保留变更记录，避免卡片失去归属。
- 首版采用团队共享的一套看板，通过项目与领域过滤；多套独立看板留待实际需求明确后扩展。

### Todo 数据与协作

- 必填：标题、所属列。
- 可选：描述、负责人、项目、多个领域、优先级、截止日期、交付链接、关联简报。
- 记录创建人、实际操作人、Agent／Model 来源及更新时间，支持评论、提醒成员和变更历史。
- 支持人工新建、编辑、移动、完成、归档；已完成卡片可重新打开。
- 关联 Timeline 简报作为进展与交付证据。移动或完成 Todo 不自动生成大量简报，Agent 可在上报时关联对应 Todo。
- 简报中的协作请求仍保留讨论语境；可转为或关联 Todo，并保留来源链接，避免复制出两份独立待办。

### Agent 管理

- 在 Go 中提供 Todo 读取、创建、更新、移动接口与列读取接口；共享列写入仅开放给网页管理员。补充 OpenAPI 与统一 CoFlow Skill 的 Todo 参考文档。
- 网页提供可复制的管理 Prompt；Agent 先读取团队看板、列及分类，再按稳定 ID 操作，不猜测列名或创建重复分类。
- 新增 `todos:read`、`todos:write` 权限；已有凭证不自动扩权。Agent 在用户授予的范围内创建和维护 Todo。
- 创建支持幂等来源标识；更新携带修订号，过期修改返回冲突，Agent 重新读取后处理，避免覆盖人工新改动。
- 移动卡片只改变状态，不触发 Agent 自动执行任务；评论也不等同于执行授权。
- 身份、团队隔离、负责人有效性及写入权限由 Go 校验。创建人／负责人可维护任务，网页管理员可管理全局；Agent 仍受成员对象权限限制，共享列仅由网页管理员管理。

### Timeline 联动

- 任务详情可发起上报，预填当前任务与分类；上报弹窗可选多个任务，简报和任务多对多关联，详情双向回链。
- 每次独立进展使用新简报 source_id，修正同次进展沿用原值；任务与简报来源标识独立。
- 上报默认不改变任务，可显式选择各任务目标列；联合提交对简报、任务、历史和通知同事务校验写入，修订冲突全部回滚并保留草稿，重试不重复执行。
- 简报已交付不自动完成任务；移动与完成任务不自动生成简报。关联和移动分别检查读取与写入权限，不通过引用扩权。
- 协作显式转为任务后保留讨论与来源，由 Todo 接管后续状态，旧协作退出待处理统计；普通关联不改变协作状态。
- 通知可定位任务，同次联合提交合并重复提醒；日报分开统计简报交付与任务完成，任务流转保留事件为 0.6 统计提供依据。

### 实施顺序

1. **A 模型与协议**：列、Todo、初始化、顺序、权限、幂等、修订与联合提交；数据库迁移和隔离测试。
2. **B 人工闭环**：默认列、任务详情、自定义列、菜单移动、筛选、归档恢复。
3. **C 看板交互**：拖拽、排序、键盘、手机与冲突恢复。
4. **D 协作与 Agent**：评论、通知、Timeline 双向关联与联合上报、协作转交、API、Skill、Prompt。
5. **E 完整验收**：中英界面、独立演示适配、端到端回归和规范文档。

### 验收标准

- 两个团队的看板、列、Todo 和凭证权限完全隔离。
- 列与卡片顺序保存到团队，刷新、换设备后保持一致；筛选状态下移动不会打乱未显示卡片的顺序。
- 项目、领域与负责人组合筛选有效，重置恢复默认看板。
- 人工与 Agent 能持续维护同一 Todo；重复提交不重复创建，冲突更新不静默覆盖。
- 桌面拖拽、键盘操作和手机移动均可用；归档列不会丢失卡片。

## 0.3 · Calendar 与甘特排期

详细规则、跨模块联动、数据／权限边界、A–F 工作包和验收清单见 [Calendar 功能与实施计划](CALENDAR_V0.3.md)。进度日历、Todo 排期、独立节点及甘特已在 0.3.0–0.3.1 发布并分别部署验收，详见验证记录；真实 Agent 长期试用与容量专项继续独立验收。

### 页面与视图

- 侧边栏新增 **Calendar**，页头继续沿用 Timeline 的标题、搜索、筛选和主要操作布局。
- 顶层分为**进度／排期／甘特**三个入口：首访无明确定位时默认进度月历，可快速看哪些日期有上报、当天列表和交付细节；点条目复用原简报及关联 Todo 详情。
- 进度及排期支持月／周，甘特独立访问；提供“今天”、前后翻页及日期跳转。上报日期按 created_at 与展示时区分组，修订不移动日期，不允许拖动简报来改上报时间。
- 按项目、领域、作者（上报）／负责人（排期）及来源／状态过滤，支持重置；数量与列表、Timeline 日报一致，简报多任务／多领域按 ID 去重。
- 甘特视图可按项目或领域分组：任务以起止时间条展示，里程碑以单日标记展示。
- 手机优先提供周／日程列表，保留日期定位与筛选；甘特支持横向浏览，并可在详情中直接修改日期。

### 排期对象

| 对象 | 展示与维护方式 |
| --- | --- |
| Timeline 简报 | 上报日历只读投影，按真实创建日期展示；保留原正文、交付、评论及任务关联，不复制简报 |
| Todo | 增加开始与结束时间；Calendar 与看板共用同一任务，修改排期双方同步 |
| 项目阶段 | 表示一段工作周期，可关联项目和领域，在甘特上展示时间范围 |
| Big Day | 标记上线日、发布会、交付日等重要节点，支持全天或具体时刻 |
| 版本安排 | 管理计划版本、目标日期和里程碑，关联待办与交付简报 |

- 未排期 Todo 放入“待排期”列表，可选择日期或拖入日历；仅有截止时间的 Todo 显示截止节点，不虚构持续时长。
- 支持拖动改期、拉伸时间范围，并提供明确的保存反馈；结束时间不得早于开始时间。
- 事件详情显示关联项目、领域、负责人、Todo 和交付链接。
- Calendar、Todo、Timeline 双向回链：改期维护同一任务；从任务发起上报使用现有弹窗，简报进入真实上报日期。任务／节点可区分当天与历史关联成果；无上报不代表无工作，也不凭空推断延期。
- 版本安排是团队项目中的业务数据；创建“v0.3 发布”日历事件不会修改 CoFlow 仓库的 `VERSION`，也不自动创建 Git 标签。

### 数据与 Agent

- 延续 0.2 的团队隔离、修订冲突检查、操作历史和凭证授权机制；补充排期 API 与 Skill。
- 上报模式只需 reports:read，Todo 排期沿用 todos 模块权限，独立节点使用新增 calendar:read/write；关联不授予来源读取权，旧凭证不自动扩权。已实现的接口写入 OpenAPI，线上可用性仍取决于实际部署版本。
- Agent 可读取排期，按授权安排或调整 Todo、阶段和节点；每次改期可追溯到操作者与变更前后的时间。
- 明确全天日期与具体时刻的区别，具体时刻以 UTC 存储，明确排期所属时区，按个人展示时区渲染具体时刻；验证跨天与时区边界。
- 首版聚焦团队内排期，不纳入外部日历双向同步、复杂任务依赖、资源自动调度和重复事件规则。

### 实施顺序

1. **A 基础契约**：来源投影、时间／时区、范围查询、计数／分页、权限与排期模型。
2. **B 默认上报日历**：月／周、有上报日期标记、当天明细、筛选、原简报／任务回链。
3. **C Todo 排期**：同一任务的计划范围、原截止节点、待排期与改期闭环。
4. **D 阶段与节点**：项目阶段、Big Day、版本计划及显式成果关联。
5. **E 甘特与 Agent**：分组、拖动／拉伸、获授权排期操作及协议和 Skill。
6. **F 联合验收**：时间／权限／缓存一致性、中英桌面／手机、合成演示与真实 Agent 试用。

### 验收标准

- 默认上报视图的日期计数、当天列表与 Timeline 日报一致，简报／任务／成果可往返，跨天新进展新建简报、原 Todo 复用，补正旧简报不伪造新上报。
- 同一 Todo 在看板与 Calendar 中保持一致，改期无需重复维护。
- 项目／领域过滤在日历与甘特中一致，Big Day、阶段和版本节点清楚区分。
- 拖动改期、时间范围调整及冲突提示有效；跨天、全天、排期时区与个人展示时区正确处理。
- Agent 能在授权范围内读取并维护排期，跨团队访问被拒绝，改动可追溯。
- 月／周／甘特桌面可用，手机能完成查看、筛选及改期操作。

## 0.4 · AI 助手

首版纳入 0.4.0，发布与部署结果独立记录，详见 [AI 助手使用与实现边界](ASSISTANT_V0.4.md)。包含独立页／侧面板、三个常见任务、团队／个人配置、DeepSeek／GLM 的 Chat Completions 与 OpenAI／Codex 的 Responses 协议适配，以及查询和待确认的任务创建／排期／简报操作。真实服务商账户仍待验证；已支持 SSE 正文流式及完整回复切换，其余原生协议、预算统计和全模块管理继续按下列范围推进，其余范围仍需独立验收。

0.4.0 已纳入历史搜索／分页／归档恢复、版本化任务模板、默认草稿的持久定时执行，以及经过清单授权的远程只读 MCP Client，范围见 [助手工作流](ASSISTANT_NEXT_STEPS.md)。真实账户联调、OAuth、外部写入和对外 MCP Server 仍未开通；本次首版不代表全部扩展方向已经实现。

### 目标与入口

- 提供内置对话助手，把自然语言请求转为各模块的实际操作，支持连续对话、跨模块处理及结果回链。
- 助手可读取当前页面的项目、领域和筛选上下文；始终显示当前团队，跨团队操作需要明确切换，不混用上下文。
- 左侧导航保留 AI 助手独立页入口，页面右侧贴边按钮展开对话面板；桌面为面板预留空间并压缩主内容，面板也可展开独立页，顶部显示当前团队、配置来源和模型。
- Timeline、Todo、Calendar 和设置页复用同一个右侧入口，保留当前页面与选中对象；同一会话连续使用。手机以全宽面板承载，桌面展开／关闭时调整主内容宽度，保持展开状态切页时预留宽度不变。
- 团队共用配置入口放在 **团队设置 → AI 服务**，由管理员管理；个人配置入口放在 **账号菜单 → AI 配置**，也可从对话顶部模型选择器直达。配置表单按“团队共用／个人”区分，显示可编辑范围，不把 AI 服务密钥混入 Agent 凭证。
- 界面突出对话、待确认变更和执行结果；结果链接直接打开 Todo、日历事件或简报。
- 首批场景：“把本周研发任务排到日历”“创建版本上线 Big Day 并关联待办”“将已交付任务标记完成，汇总为进展简报”。缺少负责人、时间等必要信息时先补齐，不猜测。

### 各模块操作范围

AI 使用与网页相同的业务接口，支持增删改查（CRUD），实际权限继承当前成员身份；不直接修改数据库，不因使用助手获得管理员权限。

| 模块 | 计划支持的操作 |
| --- | --- |
| Timeline 与协作 | 查询、新建和编辑简报，管理多链接、评论、协作请求与状态；删除或归档遵循模块已有规则 |
| Todo 看板 | 管理任务、负责人、优先级、看板列与顺序，移动、完成或重新打开任务，关联简报与交付 |
| Calendar | 查询和维护排期、项目阶段、Big Day、版本节点，批量安排或调整任务时间，保留 Todo 与日历一致性 |
| 项目与领域 | 查询、创建、改名、别名、归档、恢复、合并与排序；关联数据沿用既有分类规则 |
| 团队与设置 | 在当前成员权限内查询成员、管理邀请及可编辑设置；凭证仅提供元数据与获准的管理动作，不将完整密钥返回模型 |

- “完成任务”包括维护任务状态、排期、协作和交付记录。需要外部工具才能完成的实际工作，必须有明确授权及工具接入；没有执行证据时，不宣称已交付。
- 对话请求可拆为多个工具步骤，展示实际成功、失败和未执行的部分，不把模型生成的文本当作执行成功。
- 批量改期、删除、合并、移除成员及凭证／权限变更先展示影响范围，由用户确认后执行；普通创建和编辑给出直接、可追溯的结果。
- 写入使用幂等标识和修订号，失败重试不重复创建，冲突先重新读取；多步操作失败时保留已完成步骤，提供重试或可行的撤销入口。
- AI 操作进入模块历史，记录发起成员、助手来源、关联会话、操作对象与变更结果。网页／简报／评论中的文字是数据，不作为越权操作指令。

### 团队共用与个人配置

- 同时支持管理员维护的团队共用配置与成员自己的个人配置；两种配置均可保存多家服务商和模型。团队配置只对获准成员开放，个人配置仅本人管理和使用；团队管理员不能读取个人 Key，也不能借个人配置获得额外业务权限。
- 配置包含名称、服务商、协议类型、API Base URL、API Key、模型及连接验证状态；提供验证、设为默认、更新、停用和删除。服务商名称、协议和模型能力分别建模，不把“OpenAI 兼容”视为能力完全一致。
- **首次进入对话**：有可用且获准的团队默认配置时预选它，并显示“团队共用 · 服务商／模型”；没有可用共用配置且尚无个人配置时，在对话区直接显示“配置个人 AI 服务”的表单入口，验证通过后才能发送，不让用户发送后才遇到未配置错误。
- 已有个人默认配置时可直接继续；用户为当前团队明确选择的配置优先，其次是可用团队默认，再次是个人默认。选择失效、共用配置停用、额度耗尽或无权使用时解释原因，提供明确切换入口，不静默改用个人 Key 或切换服务商。
- 对话顶部始终显示配置来源、服务商与模型，并可切换“团队共用／个人”。费用分别由对应 Key 的持有人承担，展示可确认的用量、预算或限额，不承诺免费或无限；无服务商依据时不伪造余额和费用。
- 切换服务商或配置前说明历史对话及哪些团队上下文将被发送，并由用户确认；切换团队重新检查权限和可用配置，不把原团队对话带入新团队。配置可以跨会话复用，业务上下文不能跨团队混用。
- 本期不以平台公共免费 Key 或“官方对话额度”作为默认依赖。将来如提供托管额度，作为单独明确的配置来源与计费方案，不改变以上团队／个人选择规则；公开 Pages 演示使用合成对话，不收集真实 Key、不请求真实模型。
- API Key 由 Go 加密保存，响应仅返回掩码；个人及团队配置分别做归属与访问校验。密钥不进入模型上下文、公开日志、Git、Prompt、聊天导出或浏览器持久化明文；删除后不能继续使用旧配置，助手工具不能读取密钥原文。
- Go 统一处理模型请求、权限、预算和审计，限制协议与目标地址，阻止借自定义端点访问内部服务；设置超时、输出长度及工具步骤上限。验证连接使用最小测试内容，不发送业务上下文；用量按配置归属记录，个人账单和对话不向团队成员默认公开。

### 国内外服务商与协议适配

- 0.4 首批验收必须覆盖 **DeepSeek、智谱 GLM、OpenAI（含账户实际可调用的 Codex 模型）**，同时规划通义千问、Kimi、豆包、Anthropic Claude、Google Gemini 等常见服务。各家按独立适配及验收清单推进，标明“已验证／兼容配置／待适配”，不将仅能保存 Base URL 的服务标为完整支持。
- 适配层区分 Chat Completions、OpenAI Responses、Anthropic Messages 与 Gemini 原生等协议，统一到 CoFlow 内部消息、流式事件和工具执行结果；兼容端点保留自定义模型能力。不要求所有服务共用一种请求格式。
- Codex 在这里指通过 OpenAI 官方 API 使用账户可调用的相关模型，按模型要求选择协议；不把 Codex 应用／CLI 的登录态、ChatGPT 订阅或 Agent Token 当成通用 API Key，也不承诺模型具备平台外代码执行能力。
- 按服务商、协议与模型验证流式输出、工具调用、多轮上下文、取消、超时、限流和错误恢复；不能调用工具的模型明确作为仅对话配置，不伪造执行结果。切换模型不改变 Go 业务权限、确认和审计边界。
- 模型与能力由配置及验证选择，不在业务模块硬编码版本；上线时复核官方接口和账户可用范围，不在规划中冻结价格、配额或最新模型名称。
- 接口依据：[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[智谱开放文档](https://docs.bigmodel.cn/)、[OpenAI Codex 模型与 Responses 说明](https://developers.openai.com/api/docs/models/gpt-5-codex)。这些是适配依据，不代表 CoFlow 当前已经实现支持。

### 实施顺序

1. **统一工具协议**：基于 0.1–0.3 的 Go 接口建立跨模块工具目录、权限检查、参数校验、幂等、确认和审计机制。
2. **配置与首次使用**：团队／个人配置、权限与密钥保护、连接验证、默认选择和未配置引导；先建立服务商与协议适配边界。
3. **多服务商对话闭环**：优先完成 DeepSeek、GLM、OpenAI／Codex 验收，再扩展其他常见服务；打通流式对话、上下文、工具调用、执行结果和对象回链，覆盖任务与日历场景。
4. **全模块与验收**：补齐简报、协作、分类和设置操作，验证批量修改、冲突、部分失败、撤销及手机交互。

### 验收标准

- 正确执行任务创建、移动、完成与日历改期等跨模块请求，结果与手动操作一致，可回到原模块继续编辑。
- 每个模块提供明确的工具能力清单；不能操作的对象或无权限动作明确拒绝，跨团队访问被阻止。
- 错误参数、越权指令或页面中的诱导内容不能绕过 Go 校验；需要确认的变更在确认前不写入。
- 重试不重复创建业务对象或重复记账，过期修改不覆盖人工新改动，多步部分失败如实报告。
- 团队／个人配置可分别维护和选择，密钥与用量按归属隔离；没有可用共用配置时，有个人配置则使用明确选定的个人默认，否则先完成个人配置再开始对话。无配置不发送模型请求。
- 团队配置停用、无权使用或额度不足时明确反馈，不能静默消费个人 Key；切换服务商须明确告知上下文接收方。
- Key 不出现在响应、对话上下文、公开日志或导出内容；切换、删除配置与错误恢复有效。
- DeepSeek、GLM、OpenAI／Codex 的适配清单分别验收；流式、工具调用、多轮、取消、超时、限流与模型错误均明确反馈。仅对话模型不能执行写入。
- 独立助手页、模块内右侧面板和手机全屏可继续同一会话；配置来源和当前团队清晰，跨团队上下文隔离。

## 0.5 · Context 团队上下文

首批实现纳入 0.5.0，见 [Context 使用与边界](CONTEXT.md)。真实厂商／工具和大规模性能独立待验收，远端发布与部署结果以验证记录为准。下列为目标基线，不将完整语义矛盾检测或向量检索标为已实现。

### 目标与入口

Context 是团队主动维护的长期知识库，也是 AI 助手可检索、可维护的上下文数据源。它保存“哪些事情值得记住”，保留原始简报、Todo 和日历作为业务事实来源，不复制出另一套任务或排期系统。

- 侧边栏新增 **Context**，页头沿用现有模块的标题、搜索、筛选与新建操作；支持按项目、领域、来源模块及状态过滤。
- 沉淀团队／项目背景、重要决定、规则与约束、工作结论、风险、关键日期及需要持续关注的事项。
- Timeline 简报、Todo 卡片和 Calendar 事件提供“记录到 Context”入口，可选中重点内容保存，并自动关联原对象。
- 支持独立人工录入；一条 Context 可关联多个来源，例如一项决策同时关联讨论简报、实施任务与上线节点。
- 列表突出标题、核心内容、适用范围、有效状态与来源；详情支持编辑和查看变更历史，保留简洁的信息层级。

### 内容与生命周期

- 必填：标题、需要记住的内容。
- 可选：项目、多个领域、类型、来源引用、关联任务／事件、适用时间与复核日期。
- 记录创建人、实际操作人、人工／AI 来源、更新时间与修订号；团队信息与个人偏好分开标识，个人内容不默认共享。
- 状态支持待确认、有效、已过期、已归档；决定被新内容替代时保留历史并标记替代关系，避免旧规则继续被当作现行事实。
- 来源记录稳定 ID、引用片段及提取时的版本。原对象变化时提示复核；来源删除、归档或失去访问权限时明确标记，不静默改写已确认结论，也不通过快照绕过权限。
- 支持编辑、合并重复内容、归档和恢复；原始业务对象继续在各自模块维护，Context 不自动反向改变任务状态或日历排期。

0.5.0 增补文档／目录、关系图谱、逐层主题探索与平台内 AI Wiki：介绍骨架、Markdown 阅读、按权限目录盘点和带版本的知识引用。普通聊天分批整理仍需人工确认；页面一键操作按本次范围授权保存，来源待复核时不自动生效。详见 [Context 手册](CONTEXT.md)。

### AI 助手的长期上下文

- 外部 Coding Agent 与内置助手通过同一 Go 契约和各自实际权限访问 Context，统一 Skill 同步接入；不只提供网页私有记忆。
- 助手可以按权限检索、读取、创建和更新 Context，通过工具接口访问，不直接查询数据库；人工与 AI 使用同一份知识库。
- 按当前团队、成员可见范围、项目／领域和有效时间筛选相关内容，再将必要片段提供给模型；不把整个团队知识库一次性发送。
- 优先提供有效且适用的内容，回答或执行任务时附上 Context 与原对象引用；没有依据时明确未知，不把模型推测写成团队事实。
- AI 从简报、任务、排期或对话中提取的重点默认进入待确认。用户明确要求“记住这项决定”时可直接保存，并保留该指令的来源。
- 检索命中的相互矛盾或新旧结论需提示差异，由用户确认取舍，不静默覆盖人工维护的信息。
- Context 内容是参考数据，不是可绕过权限的系统指令。涉及任务、日历等写入时，仍走 0.4 的操作授权、确认与审计机制。
- 使用自定义 API 时明确哪些上下文会发送给对应服务商；密钥、会话及凭证不作为 Context 保存或发送。

### 实施顺序

1. **基础模型与权限**：Context、来源引用、适用范围、有效状态、修订历史及检索接口；复用 PostgreSQL 与 Go 权限边界。
2. **人工知识库**：独立页面、搜索筛选、新建编辑、归档恢复；接入简报、Todo 和 Calendar 的快捷记录入口。
3. **AI 检索与维护**：接入 0.4 工具目录，支持按需取用、引用回答、重点提取、待确认及冲突提示。先实现可验证的文本检索，再按效果决定是否引入向量检索。
4. **生命周期与验收**：来源变化复核、过期与替代关系、重复合并、跨模块与手机操作验证。

### 验收标准

- 可从简报、Todo、日历提取重点，也可独立录入；同一条 Context 能关联多个来源，点击可回到原对象。
- 项目、领域、状态与来源筛选有效，人工与 AI 更新保持一致，重复提取与重试不会生成重复记录。
- 助手能在后续对话中检索并引用已确认的背景、决策与约束；无关、过期、无权限和其他团队的内容不会进入模型上下文。
- AI 自动提取内容有明确的待确认状态，推测与已确认事实可区分；矛盾、来源变化及替代关系可见、可复核。
- 多人编辑冲突不会静默覆盖，操作与来源可追溯；归档内容可恢复，删除或权限撤销后检索与已有引用按规则同步失效。
- 关联 Context 不会擅自改变任务或排期，存储和模型请求中不泄露账号凭证、密钥或无权访问的内容。

## 0.6 · 数据统计

### 目标与首版范围

提供独立的统计入口，帮助团队回顾进展、任务推进与交付。统计来自 Timeline、Todo、Calendar 等业务事实与事件记录，支持回到原始数据，不以模型生成的总结替代计数。

- 支持最近 7 天、最近 30 天、自定义日期范围，按团队、项目、领域、成员过滤；Agent／Model 来源仅对具备来源数据的指标提供过滤，不把来源当成独立成员。
- 页面展示少量核心指标、趋势与分组明细；明确筛选条件、统计时区、数据更新时间和指标定义。手机可查看和筛选，并进入对应业务记录。
- 首批覆盖简报与交付、任务流转、排期情况及协作跟进。Context 的复核和有效性统计作为后续扩展，不阻塞首版。

| 统计对象 | 首版指标 |
| --- | --- |
| Timeline | 期间新建简报数、当前已交付简报数、交付链接数、实际参与上报成员数及趋势 |
| Todo | 当前未完成／待确认／逾期数，期间创建／完成／重开数，任务完成用时分布 |
| Calendar | 当前待排期任务数、范围内计划节点数与关联任务完成情况；不推断无证据的节点按时交付 |
| 协作 | 当前待处理协作数、期间创建与完成数；已转交 Todo 的协作独立标识，避免重复统计 |
| 分组 | 项目、领域、成员与可用 Agent／Model 来源的明细，点击可追溯原始任务、简报或事件 |

### 统计口径与边界

- 区分当前快照与期间事件：当前状态按查询时刻计算，期间新增按 created_at，完成和重开按历史事件时间。未具备状态事件的旧简报仅展示当前交付状态，不能推断历史交付日。
- Todo 期间完成数按范围内发生完成事件的任务 ID 去重；重开数另列，同任务多次完成不重复算产出。完成用时以完成事件对应的本次未完成周期计算，缺少周期起点的数据不参与分布并标明缺失数。
- 逾期仅计未完成且未归档、截止日期早于统计时区当天的任务。任务完成率必须展示分母与对象集合；首版不把“期间完成数／期间新增数”当成完成率。
- 成员维度区分简报作者、任务负责人和事件操作者。事件归属使用当时的负责人／分类快照；当前工作量使用当前归属，转派或分类调整不静默改写历史。
- 多领域对象在每个相关领域出现，团队总数按对象去重，说明分组不能直接相加。简报交付数、任务完成数、链接数分别展示，不相加为总产出；同一对象的重复链接规范化去重，不宣称链接已验证交付。
- 默认按个人展示时区统计，可明确选择时区；日期边界转换为 UTC 半开区间查询，全天日期按日期语义处理，跨日及夏令时须验证。
- 已删除简报／评论不参与内容统计；归档与删除分开处理，归档任务的有效历史事件仍可计入。删除恢复导致结果变化时遵循一致规则，查询与明细一致。
- 历史数据不足时显示缺失与覆盖起点，不回填虚构完成、排期或来源事件。活动量不等于质量、生产率或工时，首版不做成员绩效排行与无依据的 Agent 成本估计。

### 实现与权限

- Go 统一定义指标与查询，在 PostgreSQL 先实现可验证的聚合；前端只展示结果，不自行拼装权限或计算另一套口径。
- 复用模块读取权限，Agent 若读取统计结果也须具备相关源模块权限；聚合、分组数量与下钻明细同样检查团队隔离，不能通过统计泄露不可读内容。0.4 助手通过只读工具查询指标并引用口径和来源。
- 0.2 起保留任务状态、完成属性、负责人、分类与操作来源事件；0.3 记录排期调整，0.6 核对覆盖范围后决定增补事件或索引。正式查询前不引入独立数据仓库。
- 查询限制日期范围和分组规模，明细分页；先用实际测试规模评估查询计划，确有需要再增加索引、预聚合与缓存。缓存必须包含团队、权限范围、时区与过滤条件，源数据变化后按明确规则失效。
- CSV 导出、订阅报表、外部 BI、成本核算及自定义指标不纳入首版必交范围，按实际需求另行设计。

### 实施顺序与验收

1. **指标与样本**：固定指标字典、事件覆盖范围、时区及去重规则，编制可手算的合成样本。
2. **聚合与隔离**：实现 Go 查询与读取接口，验证权限、跨团队隔离、源数据变化和查询成本。
3. **页面与下钻**：完成核心指标、趋势、分组、筛选和原始记录跳转，适配中英与手机。
4. **助手与验收**：接入只读工具，验证返回值与同条件网页一致，记录实际规模和性能限制。

验收要求：合成数据可手算对账；重复上报、关联多个任务、重开再完成、转派、多领域、归档、删除恢复、跨日与夏令时均有确定结果；指标与下钻一致；无权对象不出现在数值、明细或模型上下文中。统计不改变任务、日历或简报，已有版本不因新增路线图自动更新。
