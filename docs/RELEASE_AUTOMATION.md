# 可续跑的手动发布工具

入口为 [`scripts/release/run.mjs`](../scripts/release/run.mjs)。它减少 GitHub 页面操作、重复查询和 Agent 重读日志；版本、公开提交审查及当次发布／部署／上报授权仍由维护者决定。不会自动改版本、暂存文件、创建提交、建立定时任务或添加发布触发器。

## 公开逻辑与私有配置

| 位置 | 内容 | 是否进入 Git |
| --- | --- | --- |
| `scripts/release/` | 通用入口、检查点及工作流跟踪逻辑、无真实连接信息的示例 | 可以，审查后提交 |
| `.local/release/config.json` | 当前实例的仓库、Pages、私有适配入口及本机连接配置 | 不可，Git 忽略，0600 |
| `.local/release/adapter.py` | 当前实例的 SSH／备份／部署／报告实现 | 不可，Git 忽略，0600 |
| `.local/release/runs/<tag>-<source-prefix>/` | 工作流 ID、镜像摘要、已验证阶段、私有运行证据 | 不可，目录 0700／文件 0600 |
| 用户私有凭证目录 | 既有 SSH 私钥及 CoFlow Token | 不可，不复制进配置或检查点 |

通用代码不包含真实实例地址、团队身份或凭证。示例复制到 `.local/release/config.json` 后填写；`.local/release/` 设为 0700，配置及适配文件设为 0600。入口拒绝链接形式的私有路径以及不安全权限，不允许把适配脚本放进公开目录。凭证不放入参数、环境转储、提示词、GitHub Secrets 或公开日志。

工具执行前检查 Git origin 与配置仓库一致、工作区干净、源提交版本合法、公开路径及常见凭证特征。自动扫描不能识别所有敏感正文，提交前仍须审查暂存差异；工具不替维护者自动 `git add` 或 commit。

## 使用

前提是 Node.js、Git、GitHub CLI 可用。实际操作 GitHub 前，先由维护者完成 `gh auth login` 并用 `gh auth status` 检查；不从浏览器提取 Cookie、复用 CoFlow Token 或自动申请额外权限。服务器／上报适配需要本机已有的独立凭证。

先完成实现、验证及版本记录；明确发布新版本后按 [VERSIONING](VERSIONING.md) 更新版本和对应的 `docs/releases/vX.Y.Z.md`，审查并提交。**当前 VERSION 对应的标签若已存在，入口不会覆盖它来发布另一份源码。**

```sh
# 默认只读本地数据并展示计划；不连网络、不写检查点。
npm run release -- --checks --push --release --images --pages --server --report

# 只有当次明确授权了这些动作，才添加 --execute。
npm run release -- --checks --push --release --images --pages --server --report --execute --wait-seconds 600

# 查看私有检查点的简短状态，不访问远端。
npm run release -- --status --source <完整40位源码SHA>

# 在同一源码与配置下重跑，复用已有阶段和工作流。
npm run release -- --images --pages --server --report --execute --source <完整40位源码SHA> --wait-seconds 600
```

没有 `--all` 或默认双报。选择哪些阶段就授权执行哪些写入；`--ci` 是发布类阶段自动增加的只读前提，不会补发源码推送。单独 `--pages` 不部署私服；单独 `--server` 不发布镜像，需要该源码已有验证过的镜像检查点；单独 `--images` 不创建 Release，需要已有稳定发布。

GitHub 镜像／Pages 工作流从 main 触发；新触发时 main 必须精确等于所选源码，避免 Pages 发布了另一份代码。`--source` 固定恢复对象；本地 `--checks` 只检查 HEAD，旧源码依赖它自己的精确 CI。已有远端标签和正式 Release 必须指向固定源码，不移动标签、不重写历史、不强推。

## 阶段与证据

| 开关 | 实际执行与边界 |
| --- | --- |
| `--checks` | 本地版本、文档、类型及仓库 JS 测试。Go race／生产构建以精确源码 CI 为准，不假称本地已重跑 |
| `--push` | 仅推送所选已提交源码到 main，不自动暂存／提交，不强推 |
| `--ci` | 等待同源码、main、push 事件、指定 CI 工作流成功；失败即停 |
| `--release` | 校验或新建固定标签及正式 Release，正文读取该提交中的版本发布说明 |
| `--images` | 手动触发 images.yml，复用 run；匿名核验 GHCR 内容摘要与 amd64 平台 |
| `--pages` | 独立触发 pages.yml，核对规范六文件与源码一致，确认 API 为 404 |
| `--server` | 调用仅本机存在的服务器适配；必须返回当前版本／源码的已验证证据 |
| `--report` | 调用本机上报适配；遵守私有配置中的部署前提及当前项目绑定 |

私有适配通过 stdin 接收阶段、版本、源码、已验证结果、镜像摘要和运行目录；stdout 只能返回 JSON：`verified: true`、匹配的 `version`／`sha` 及必要证据。不向 hook 传环境转储或 Token。入口不回显子进程的原始输出，避免把私密错误正文带入 Agent 上下文；故障时在本机核查，不上传整份私有检查点。

当前项目的本机服务器适配复用已审查的私有部署模板，并动态绑定版本、源码和迁移数；整个备份／切换持有服务器锁。完整解码备份、保持原加密主密钥、仅替换 API／Web、核对 source label／数据保留／迁移／健康／匿名权限和规范下载。已有成功部署仅在收据、运行镜像及线上验证匹配时复用。模板针对当前实例；未来数据库结构或 Compose 约定变化时，先审查更新模板，不能假设能部署任意未来架构。健康失败沿用应用回滚，不自动恢复数据库覆盖新数据。

本机上报适配读当前项目已验证绑定，逐个校验配置选中的团队、实际权限和凭证路径，复用稳定任务／报告身份，回读关联后记成功。日期／报告意图先私有记录，未知写入结果跨天重试也保留原 source_id；不因重试重复建任务、空报或关闭其他验收待办。**多团队只是本项目私有配置选择，不是公开工具或 Skill 的默认行为。**

## 中断与恢复

- 退出码 **0**：所选阶段完成；**2**：仍在等待远端，按相同参数续跑；**1**：需核查故障。`--wait-seconds` 为本次等待预算，默认 45 秒、最多 3600 秒，不代表发布超时失败。
- 工作流请求前先保存触发意图；即使请求响应丢失，续跑也只寻找同源码的后续 run，不自动再触发。多个候选 run 会停止；若没有 run 出现，先在 Actions 核实，再审查修正私有意图，不盲目重试触发。
- 流水线锁防止同一源码的两个 runner 同时写状态。进程异常退出留下 `runner.lock` 或 `.tmp` 时，先核对 PID／实际进程和远端结果，确认已停止后只清理对应私有临时文件；不要删除整个运行目录或重建任务。
- 已完成阶段显示 `previously verified`，指上次成功检查点，不是声称刚刚重新验收。需要重新验收时，由维护者核查并清理该阶段完成记录；不要改 SHA、摘要或报告 ID 来掩盖失败。
- 配置内容改变会拒绝复用旧检查点，避免把旧环境结果误用到新目标。先审查并迁移相应私有记录。

## 本地验证边界

`npm run test:release` 使用一次性仓库、假 GitHub／Registry／hook，覆盖整条执行与续跑、默认计划无外部命令、授权阶段隔离、未知触发结果不重发、错误源码／状态拒绝和私有文件／输出边界。不使用真实团队、Token、服务器或 GitHub 登录。

私有适配另有仅本机的合成测试；实现此工具时未触发真实推送、发布、部署或 CoFlow 上报。真实首次运行仍需当次授权、CLI 登录和现场验证，不能用模拟通过宣称真实发布已成功。

2026-11-07 的 0.4.2 已完成首次获授权的真实发布／镜像／双环境部署，见[验证记录](VERIFICATION.md)。本机直连 Pages 失败时，独立 HTTPS 核验在既有实例出站网络完成，并在私有检查点记录验证方式；入口本身不会自动把网络失败标为成功，也不会自动改用私有实例。新增环境或修改适配仍需对应授权和现场验证。
