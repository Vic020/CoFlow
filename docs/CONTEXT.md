# Context、阻塞与持续委托

状态：Context 随 0.5.0 源码发布，0.5.1 增加助手运行任务跟踪；Skill 1.5.0。平台入口、HTTP 和唯一 Skill 共用 Go 权限契约。各环境实际部署结果见 [验证记录](VERIFICATION.md)。

## 共同交付

Todo 管行动，Calendar 管时间，Timeline 保留进度与交付，Context 记住有依据的背景、决定、规则与约束。原模块始终是业务事实来源。记录到 Context、前置任务完成或授予委托，都不会自行启动 Agent、移动后续任务或发布简报。

## 阻塞依赖

Todo 阅读详情中的“阻塞与依赖”记录前置任务、等待成员和解除条件。前置任务须为本团队另一有效任务，不允许循环，最多 20 项。前置任务未完成／归档时依赖仍阻塞；人工条件由维护者明确标记满足。复用原 Todo 修订、历史和操作幂等。

手工完成、拖入完成列、验收通过、联合上报、列完成属性修改和助手推进均保留阻塞检查。前置任务完成或重开会提示后续任务负责人，Calendar／甘特使用同一派生阻塞状态。依赖解除不自动完成任务或调整排期；已完成的后续任务不被自动重开。

## 持续委托

Todo 页及任务详情可管理委托。网页登录的任务维护者可向一名当前成员授予单任务委托；项目范围仅管理员授予。可选择本人供自己的 Agent 凭证使用；受托身份按成员，不区分同成员的不同客户端进程。选择编辑内容、推进状态、评论、调整排期中的动作，期限最多 90 天。撤销只移除该委托提供的权限，不删除原有成员权限。变更范围需先撤销再重新授权，保留授权／撤销记录和修订。

Agent 可读取自己的相关委托，并在用户原有执行指令、实际 Token scope 和对象权限内使用。每次写入重新验证有效期、撤销、授权人当前成员关系和权限；项目授权人失去管理员权限后不再授权项目范围。编辑委托不能顺带改负责人、项目、验收、来源归属或阻塞；仅排期委托不能夹带正文修改。项目合并会撤销旧项目委托，避免扩张到目标项目全部任务；Context 分类随原分类迁移并留历史。验收决定、分配／提醒权限和外部 Agent 调度不在本批委托动作中。助手仍需操作确认卡，定时任务仍不推进 Todo。

委托列表对授权人、受托人及管理员可见，保留过期与撤销状态；无关普通成员不可见。可见性不赋予受托人撤销、延长或扩大委托的权限。

## Context 页面

顶部使用紧凑的列表／探索／图谱切换和统一筛选控件。阅读页提供“返回列表”，点击顶部“列表”也会退出正文并回到列表，保留当前筛选与分页；进度条固定在筛选区域右侧，不再额外占行。

桌面端搜索、AI 提取和新建 Context 与页面标题同行；手机端保留标题与主操作同行，搜索放在下一行。主操作高 30px，正文工具高 28px，目录 AI 与新增按钮成组靠右。执行结果在按钮原位短暂显示，错误在操作附近提示，停止按钮位于原按钮内，避免新增提示行和布局抖动。

目录 AI 只整理该分组当前可见且未归档的文档，不扩大到其他目录；图标按钮显示运行／完成状态，并在旁边短暂提示结果。目录「+」打开介绍文档草稿。离线演示明确提示仅模拟整理、未调用 AI、原文不变；真实实例配置可用模型后才执行实际整理，没有模型配置时打开个人 AI 设置。

侧导 Context 沿用顶导项目／领域／成员过滤。支持正文搜索、类型／状态／来源过滤、独立录入、居中阅读和编辑、有效日期与复核日期、历史、归档恢复和合并重复内容。当前文本检索为不区分大小写的字面匹配；按更新时间分页，不承诺编辑期间的固定快照。

Todo、Timeline 和独立 Calendar 节点提供“记录到 Context”。同一来源的同一内容重复提取使用稳定标识并复用记录，不降级已确认事实；编辑冲突不覆盖人工整理。可关联多个来源，保存 ID、摘录和提取时版本；不复制另一套任务或排期。来源变化／归档或复核到期在读取／刷新时显示“需复核”；原正文不自动覆盖。复核前须阅读原对象；到期复核日期在明确复核后清除，可另设下一日期。冲突保留草稿，新建来源引用可在核对原对象后更新版本，不必丢弃事实正文。页面聚焦和助手写入会重新检查已有记录，来源失效则隐藏详情。来源失效或无原模块读取权限时隐藏关联内容，不通过历史快照泄露来源。

状态为待确认、有效、已过期、已归档；有效截至日期按 UTC 自然日包含当天，次日派生为过期。恢复回到待确认。普通草稿的审核与复核保留显式操作；下述一键流程已包含本次自动整理授权，来源有效时可直接保存生效。合并保留目标正文、合并来源，并将重复项归档回链，双方修订均校验；不同结论需要先由人决定，不自动语义合并。同范围同名不同正文的记录显示核对提示，非完整语义矛盾检测。

个人内容只对创建人可见，团队管理员也不能读取；改为团队可见不会公开旧个人历史正文。团队内容由创建人或网页登录管理员维护。来源检查覆盖当前内容、历史、检索结果、分页总数与写入重放；前端沿用身份隔离与刷新保留内容的加载规范。

## 文档目录与平台内 AI Wiki

Context 除事实记录外新增 Markdown 文档和目录索引，可维护项目介绍、领域说明、工作约定及知识导航。左侧目录按项目／领域浏览；文档与事实可挂在文档／索引下，最多 12 层。选择后在页面内阅读，支持 Markdown 页内知识链接和结构化来源的反向引用；编辑、审核、历史仍使用同一居中弹窗。项目／领域目录上的“+”只创建介绍草稿骨架，不根据分类名称编造真实业务知识；演示站有合成项目介绍、领域介绍和子文档示例。

`GET /api/v1/context-tree` 返回当前权限及全局范围过滤后的目录元数据，不返回正文，最大受每团队 1000 条上限约束。父级不可读或被筛选排除时将条目投影到当前目录顶层。上级须为同项目／同可见范围的文档或索引；个人目录还须同创建人。可在编辑中调整上级，Go 拒绝目录循环与引用循环。

来源增加 `kind: context`，保存被整理记录的 ID、版本与摘录。派生文档读取时递归检查来源当前权限，来源变化、过期、待确认或待复核会提示复核；个人来源不可直接引用到团队文档。引用链最多 12 层、单次链检查 128 次访问，超限内容不作为可读事实；不承诺大规模图查询性能。Markdown 链接只是导航，需要追踪版本／可见性的依据使用结构化来源。

助手新增“整理 Context Wiki”模板及 `read_context_tree` 只读工具。目录每次向模型最多返回 50 项，正文每次最多 4000 个 Unicode 字符，按 offset 继续读取；不把目录盘点或正文截断当成全量整理。用户明确指定全部可读 Context 时可按该范围分批，否则先限定项目／领域。普通聊天每轮最多五条文档／索引草稿并保留确认卡，保存后仍待审核；页面一键自动流程见下一节；需要说明已读、未读、重复与冲突，不能声称后台持续整理。它不是第三方 llm-wiki 引擎、文件系统同步或向量知识库，也不会为真实团队自动创建介绍内容。

### 逐层探索

Context 新增“探索”，与列表／图谱并列。入口只展示有可读知识的顶层项目、领域或团队主题；进入后先看主文档，再按实际父子关系选择当前层的分支，优先展示下级较多的主知识点。每层先展示八个分支，可继续展开本层，不一次铺开全部知识，也不会把引用关系当成前置技能或虚构未解锁节点。

面包屑、返回上一层及浏览器返回均可切换路径。当前位置用 URL `knowledge_view=explore&explore_topic=...&explore_node=...` 记录，可直接返回或收藏；节点不可见／不存在时回到当前可见主题，不恢复旧快照里的名称。只在进入节点后按需读取该记录，支持就地预览、来源跳转和居中阅读全文，阅读不退出探索。

“本次已浏览”只表示本次视图中的成功读取，刷新或重新进入后重置；不是掌握程度、解锁权限、任务完成或验收。每层保留 AI 整理，文档／索引下可新增实际分支，复用原 Context 修订和授权规则，不根据游戏外观自动写业务状态。

探索沿用全局范围与本页搜索／状态／类型／来源过滤。过滤匹配项时保留同一可读目录中必要的上级路径，父级已被权限或全局范围排除时作为当前顶层展示，不补出隐藏节点。`/context-tree` 同步支持 q／kind／source 元数据过滤，无正文／历史返回，沿用最多 1000 条知识及 12 层目录限制。不存在新增后端知识或训练进度存储。

### 知识关系图谱

Context 提供列表／探索／图谱切换，项目、领域、成员与本页搜索／状态／类型／来源筛选沿用同一范围。筛选首先作用于 Context，图谱再带出这些知识实际引用的来源、父级及原模块中的明确关联；这些直接关联节点可以位于筛选范围外，但必须当前可读。不是扫描全团队后猜测关系，也不等同于 AI 语义相似图。

六类节点为 Context、项目、领域、Timeline 进度、Todo、Calendar；连线区分项目／领域归属、目录父子、结构化来源、任务交付进度及 Calendar 原记录已有关联。支持拖动画布／节点、滚轮和按钮缩放、适应画布、类型显隐、标签、选中高亮直接关系及可用键盘操作的节点列表。双击或详情按钮打开原记录；项目／领域节点可直接更新全局筛选。图谱模式写入 URL，支持直接进入和返回。

Go `GET /api/v1/context-graph` 返回授权后的节点／边元数据，不包含正文、引用摘录或历史。个人知识、不可读／已删除来源的派生节点与数量不暴露，源模块节点仍要求对应读取权限；原接口错误不会伪装为无关联。默认不展示归档知识，可通过状态筛选查看。

首版最多展示 120 条匹配知识、600 个节点、2400 条边，达到上限显示精简提示，可缩小筛选范围继续查看；不会伪装为完整图谱。布局由本地确定性算法计算，不连接外部图谱／绘图服务，不新增依赖或持久化另一份业务关系。未做大规模性能承诺。

### 一键自动整理

Context 右上角为“AI 提取”和“新建 Context”。前者使用当前已验证的默认／选定 AI 配置，自动读取、去重、整理与保存，不打开聊天或要求再次点确认卡。若缺少配置，直接进入个人 AI 配置。文档正文、目录分组，以及 Todo／Timeline／Calendar 原记录提供就地 AI 入口；手工录入仍保留。

当前范围内已有知识时，浏览器先固定目录 ID 清单并逐条处理，展示进度，可停止后续条目；当前已发出的请求可能完成，已保存内容保留。传输结果未知时复用该条 request_id 和初始清单重试；明确的单项失败使用新的尝试编号，已有产出保留。运行由工作区级控制器承接，站内切换页面继续执行，初始范围不随新页面筛选改变；关闭页面不再启动后续请求，已发出的服务端请求仍可能保存结果。无现有知识时从当前范围的原模块记录开始有限检索，返回真实覆盖范围，不把未读取的记录说成已整理。每条请求最多五项 Context 变更，长范围按条连续执行，不承诺一次模型调用能整理全部数据。

浏览器专用 `POST /api/v1/assistant/context-auto` 接收 `request_id/config_id`、项目／领域／成员及可选 `source_kind/source_id`。入口本身代表本次自动整理授权：服务端限制可用工具到读取和 Context 维护，重新核对来源／范围／修订，自动执行 Context 保存；来源当前有效且无需复核时自动生效，来源待确认、过期或变化时保留待复核状态，冲突与失败明确返回。不扩展到任务推进、进度发布、日历排期、外部工具或定时任务。

操作保留助手历史、实际 AI 来源与修订记录。同主题优先使用初始目录中已有的可维护文档，新建使用稳定身份避免重试重复。普通聊天／模板依旧使用原确认卡；外部 Agent Token 不能调用网页登录专属自动执行入口，也不能借此扩权。离线演示只模拟流程、保留或复制合成来源，不调用真实 LLM，不将复制结果声称为模型提炼。

### 写作与整理约束

- **说人话**：先说结论，用具体、简短的表达；必要术语首次解释，标题能看出主题。不写流水账、套话或整页空模板，事实、建议和未决问题分开。
- **用图说清关系**：流程、依赖和架构适合用小图；比较、映射适合用表格，并保留一句文字解释。当前阅读器支持 Markdown 表格与代码块中的文本图，不将 Mermaid 源码冒充已渲染图，也不使用虚构图片地址或外部画图服务。
- **围绕主体收敛**：同主题优先补充已有主文档和章节；内容较多时用一份概览／索引带子文档，形成清晰目录。不同主题、读者／可见范围或足够独立的细节再拆页，避免一次上报一页、重复介绍和过深目录。
- **整理保留依据**：创建、移动或合并前查找已有归属，保留来源、历史与链接；不静默合并冲突，不跨个人／团队可见范围，不删除原任务或上报。整理结果仍通过修订和确认流程。

这些约束已写入统一 Skill、助手通用指引及知识模板；在用户点击一键操作时自动应用，不因规范更新而自行改写现有文档。

## Agent 与 AI 助手

能力发现 `todo-blockers-v1`、`delegations-v1`、`knowledge-v1`；`knowledge-v1` 是长期 Context，旧 `context-v1` 仍表示有限接续事实，不混用。旧 Token 不扩权，新 Token 可选 `context:read`／`context:write`，写入必须有读取权限，来源另需原模块读取权限。

统一 Skill 的 [Context 参考](../skills/coflow/references/context.md) 和 Todo 参考说明读写、复核和权限边界。`GET /context` 和 `GET /context/:id` 可检索／读取，POST／PATCH 维护；委托使用 `/delegations`。接口以前缀 `/api/v1` 调用，详见 [OpenAPI](openapi.yaml)。Agent 提取写为待确认；网页登录确认后才成为有效事实。

助手新增 `find_context`、`read_context`、`read_delegations` 和 `propose_context`，提供独立“记住决定”模板，不改旧模板版本。按当前筛选取必要片段；默认检索排除未确认、过期、未来生效或待复核内容，并返回原对象链接；可显式检索 pending 用于去重／审核，不能将其当成既定事实。普通聊天创建／更新先出确认卡，确认后仍保存为待确认；一键自动流程具有单独的本次范围授权，不把推测或失效来源伪装为已确认事实。Context 是参考数据，不能覆盖系统指令或绕过原业务确认；不应保存或发送密钥／凭证，服务端也拒绝已知凭证形式。

### 整理时机与初始化

在形成明确决定、可复用规则、阶段交付和交接时，Skill 与助手主动检查是否有值得沉淀的新知识；普通进度或跨天不触发逐条归档。先读已有记录并去重，冲突交给人确认。已有授权覆盖 Context 维护时可提出待确认草稿，否则先简短建议，不把单次上报扩展为知识写入。

助手任务模板新增“初始化 Context”：指定项目，可选时间范围；先读取已有知识及相关 Todo／Timeline／Calendar 原始记录，每轮最多提出五条有依据的草稿，并说明覆盖范围、未读内容和冲突。未指定时间范围时从有限近期记录开始，不声称全量整理。普通聊天模板确认保存后仍为待确认事实；页面一键流程按下面的自动执行规则处理，不会创建定时整理或改变任务。离线演示展示模板及能力说明，不用合成进度编造知识。

现有 changes 游标不包含 Context／委托变化；每次授权接续及引用决定前重新读取相关知识和委托。handoff 按权限附带有限相关知识与委托，不承诺事务快照或全量。页面提供本次授权范围内的一键提取，未提供向量检索、后台持续知识提炼、自动调度、外部写工具或 CoFlow MCP Server。

## 存储与验收

复用 PostgreSQL `todo_boards.document` 的事务锁与 JSON 模型保存阻塞、委托和 Context；外部看板响应不返回 Context／委托内部集合，无新增 SQL migration。首批每团队 Context 上限 1000 条、来源每条 20 项、正文 20 KB；大规模索引／独立存储和性能专项后续按实际数据验收。旧程序会忽略新 JSON 字段，回退前需协调数据／备份，不能假定可用旧程序安全写回。

离线 Pages 仅使用合成内存数据，刷新重置，不连接真实模型／MCP／团队服务。测试使用一次性 PostgreSQL、合成身份和协议服务；两种 Agent 身份验证接续／冲突不等于真实 Coding Agent CLI 实测。用户不提供测试账号时，不调用真实厂商、不创建生产配置；真实 DeepSeek／GLM／OpenAI、MCP 服务和实际两工具联调保持“未实测”，不以模拟结果替代。

## 查看 AI 操作进度

发起后，按钮旁的“查看任务”、助手全屏左栏“运行任务”、窄屏或侧面板的同名入口均可打开统一列表；右侧助手入口显示活动任务数。列表展示本批文档总数、已处理数量、保存及待复核数量、错误、来源页面、Context 结果链接和已返回的助手记录。停止只阻止后续文档，当前请求可能继续保存；继续只处理未完成部分，重复点击不新增相同活动操作。

记录属于当前浏览器会话，并按账号和空间隔离；只缓存内部 ID、计数、状态和安全来源路径，不缓存正文、模型回复、错误正文或凭证。整页刷新后，原运行中操作显示“状态待确认”，不自动重新调用模型；先查看服务器已保存的助手历史及原对象，再决定是否重新发起。该列表不是服务端后台任务队列，不承诺关页后续跑、跨设备实时运行状态或取消已进入服务端的单次请求。离线演示只模拟处理，不调用真实 AI。
