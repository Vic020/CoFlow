# 持久化本地团队与部署模拟

用于在自己的电脑配置 AI 服务、练习协作及验证部署，不是每轮结束就销毁的验收库。与公开离线演示、现有开发库和远程实例分开；不会导入线上账号、数据、Key 或 Agent 绑定，也不发布镜像、创建 Release 或部署远程环境。

| 入口／资源 | 用途 | 数据与配置 |
| --- | --- | --- |
| 现有离线演示，例如 `http://127.0.0.1:3102` | 无账号的公开演示预览 | 合成数据，刷新重置，不调用真实 AI |
| `http://127.0.0.1:3103` | 持久团队模拟；容器版与开发模式共用入口 | 真实账号、Go 权限、PostgreSQL 持久卷、加密的 AI 配置 |
| `127.0.0.1:18083` | 本机开发前端转发到 Go API | 仅回环监听；接口仍需登录与对象权限 |
| `coflow-local-team_database` | 专用 PostgreSQL 17 卷 | 启停、重建 API／Web 不删除数据 |
| `.local/local-team/` | 本机配置、初始登录信息与备份 | Git／Docker build 忽略；目录 700、敏感文件 600 |

## 初始化与日常使用

需要 Docker／OrbStack 与 Python 3.9+；前端热更新模式还需要 Node.js 24 及 `npm ci` 安装的依赖。

```sh
# 首次创建本机配置、构建并启动完整环境、初始化本地账号及练习数据。
npm run local:team -- up

# 以后启动已有镜像，保留数据和密钥，不重新构建。
npm run local:team -- start

npm run local:team -- status

# 只停止本环境，不删除卷、配置或登录账号。
npm run local:team -- stop
```

打开 [本地团队](http://127.0.0.1:3103)。初始账号为 `owner@coflow.test`，随机初始密码只写入本机 `.local/local-team/ACCESS.md` 和 `access.json`，命令行不输出密码。首次登录后可在个人设置改密码；修改后的密码不会自动回写初始文件。始终使用配置里的完整 origin，不随意将 `127.0.0.1` 换成其他主机名。

默认创建“本地模拟空间”和“本地模拟项目”，提供三个练习任务、一条真实关联的初始化进度、一个日历节点、项目介绍及带 Todo／Timeline／Calendar 来源的子文档。它们明确为本地练习数据，不代表真实交付；初始化不发起外部模型调用，不建立真实模型配置、Agent Token、定时任务或 MCP 连接。完成后重复启动不会覆盖你后来编辑的示例、账号或配置。

## 配置并验证 AI 能力

1. **个人模型**：左下角账号菜单 → 个人 AI 设定 → 模型服务。**团队共用模型**：空间设置 → AI 服务。填写自己用于本地测试的配置，先验证、再保存；两种配置仍遵守账号／团队权限。
2. 联网服务在各自的独立配置页设置，需要时在对话中主动开启；初始化不会复制或读取远程环境的服务密钥。
3. 在助手中选中本地模拟项目，先测试“读取项目进度，给出来源，暂不写入”。再测试生成任务草稿、确认保存和日历排期。对话写入仍经过原模块确认及 Go 权限校验。
4. 在 Context 点击 AI 提取／整理，从按钮旁“查看任务”或助手“运行任务”查看进度、保存内容、错误和助手记录；批处理在站内切页继续，刷新后未确认请求不自动重跑。

配置之后主动验证或发起操作，会真实请求你选择的厂商，可能计费；先使用练习数据和自己的测试额度。环境初始化及自动检查不代替真实厂商兼容性验收。本地环境不自动替换当前项目已绑定的远程 CoFlow 空间；如需测试外部 Coding Agent，使用单独的测试项目目录和明确的本地实例安装提示词。

## 前端热更新模式

```sh
# 先确保 start／up 已就绪，再在前台运行：
npm run local:team -- dev
```

该命令只暂停本环境的网关，在同一个 `3103` 入口运行 Next.js 开发服务，转发到持久 Go API。账号、Cookie、数据和 AI 加密密钥共用；使用独立的 `.next-team` 编译目录，与离线演示 `.next-pages` 分离。`Ctrl+C` 退出后恢复容器版入口。需要保持终端运行，不创建系统自动化任务。

这是**前端**热更新；修改 Go 或希望验证生产构建时，先备份，再退出 dev 并执行 `up` 重建本地镜像。`start` 使用上次构建产物，不会把未构建源码自动更新到容器。默认容器版使用与远程部署相同的 Go／Next.js Dockerfile、PostgreSQL 和 Caddy 同源代理；本机网关配置随镜像构建，不依赖宿主机文件绑定权限。

本地仅用回环 HTTP，`Secure Cookie=false`；远程 HTTPS 仍必须使用 `Secure Cookie=true`。本环境不代替公网 HTTPS、跨机网络、容量或故障恢复专项验收。

## 备份与密钥保留

```sh
npm run local:team -- backup
```

备份存入 `.local/local-team/backups/`，权限 600，成功前做完整解码校验，不自动删除旧备份。`instance.env` 中的固定 AI 加密密钥必须单独妥善保留；只有数据库而没有原密钥，将无法解密已有模型／联网配置。

`init` 只在不存在配置和旧卷时生成随机值；已有配置保持不变。如果发现旧数据卷却缺少配置，会停止，要求恢复原 `instance.env`，不会生成新密钥冒充恢复；已有初始化记录但数据卷丢失或数据库变为空库时，同样会停止，不静默建立空白替代环境。不要运行删除数据卷的命令，不要把 `.local/`、访问文件、备份或私密环境加入 Git／公开镜像。正常命令没有重置／删库选项。

## 本机代理 Fake-IP 与模型连接

模型服务域名如被代理解析到 `198.18.0.0/15`，Go 的公网地址检查会拒绝连接；API Key 正确也不能验证。不要关闭 SSRF 检查或放行保留地址。优先在代理的 Fake-IP 排除规则中为所用服务商域名使用真实 DNS。

必要时可在本机私有 `.local/local-team/network.compose.yaml`（普通文件、权限 600）为 `api` 配置 `extra_hosts`，仅绑定经可信 HTTPS DNS 核对的公网地址，保留原域名和 TLS 校验。`local:team` 会合并该文件；不使用明文 IP 替换 API Base URL，不复制到线上或公开 Git。公网地址可能变化，连接失败时重新核对；恢复正常 DNS 后移除覆盖并重建本地 API。该文件可包含本地网络信息，保持 Git 忽略。
