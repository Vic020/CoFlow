# CoFlow 0.4.1 — Delivery review and Agent handoff

## Changes

- Optional Todo acceptance criteria, designated reviewer, submission evidence, approval/return history, notifications and completion guards. Ordinary tasks retain direct completion. An assistant may prepare submission/withdrawal, but cannot approve or reject on the reviewer's behalf.
- Permission-scoped Agent change cursors and compact project/task handoff context. Assistant task operations use explicit confirmation, revisions and idempotency. New resume/advance templates have separate versions; old templates and scheduled draft boundaries remain intact.
- Named AI providers, editable model suggestions and **Fetch models**. Listing goes through Go with the existing public-HTTPS/SSRF protection and saved-key ownership/address checks. Failed listing preserves custom entry and suggestions; it does not verify a model or change the current selection.
- Keep the stream toggle on one line in the assistant toolbar. Documentation and synthetic demo cover the delivery workflow.

## Upgrade and validation

Application **0.4.1**, unified Skill **1.4.0**. Skill changes are compatible capability discovery and Todo acceptance guidance; older servers retain module fallbacks. Existing local Skill installations are not updated automatically.

Back up the private database and environment before deployment. Additive migration **014** records compact change events; it does not copy report/task bodies. Preserve the existing `COFLOW_AI_ENCRYPTION_KEY`. Todo acceptance uses the existing task document and requires no extra migration. Context here is a scoped handoff summary, not the planned 0.5 knowledge base or autonomous delegation.

66 JavaScript tests, type/i18n/docs/version checks, isolated team/demo webpack builds, complete collaboration/review Go race tests and targeted model-discovery race tests passed locally. Release-source main CI must pass before image publication. Real provider accounts, external MCP and cross-session Agent/capacity acceptance remain separate; no production model config, schedule or MCP connection is created by this release.

Source, CI, immutable image digests and the two independent deployment outcomes are recorded in [verification](../VERIFICATION.md). GitHub Pages remains a synthetic offline demo with no real API or credentials.
