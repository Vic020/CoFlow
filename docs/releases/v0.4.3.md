# CoFlow 0.4.3 — Account AI settings, independent web services and skeleton loading

## Changes

- Personal model configuration and defaults now belong to the account and work across its workspaces. The account menu separates profile/password settings from a dedicated Personal AI settings dialog; workspace Settings retains shared configuration.
- Independent web-service configuration supports Tavily, DeepSeek, Exa and Firecrawl search/fetch with supported chat models. Keys, verification and defaults are separate from model services. Access remains opt-in per turn, bounded to three external requests, and disabled for jobs and the offline demo. No existing model key is copied automatically.
- Structure-matched skeletons cover initial workspace, Timeline, Todo, Calendar, settings and assistant reads. Background refresh retains valid content and uses fixed progress strips to keep headings and actions stable.
- GitHub maintenance and Agent handoff guidance documents action boundaries, resumable execution and compact CI observation. CI, images and Pages use pinned Node.js 24 Actions and Ubuntu 24.04 runners.
- Current guides and bilingual README clarify shipped collaboration capabilities and the account/web-service settings entry points.

## Upgrade and validation

Application **0.4.3**; unified Skill **1.4.0** unchanged. Migrations **015** and **016** bring the total to **16**. Back up the database and preserve the existing `COFLOW_AI_ENCRYPTION_KEY` and private environment before upgrading.

Migration 015 retains existing personal configuration IDs, revisions, verified timestamps and encrypted bytes, including the legacy associated-data context. Multiple personal defaults converge to one account default without deleting other configurations. Team configuration stays team scoped. Migration 016 adds separately encrypted web-service configuration; it does not copy provider keys.

The old application cannot use the migrated personal configuration scope. A rollback requires a coordinated schema/recovery plan; replacing binaries alone does not restore old personal configuration behavior. Never restore a database over new production writes automatically.

Implementation verification includes 75 JavaScript tests, type/i18n/docs/version checks, isolated team/demo webpack builds, targeted Go race and disposable PostgreSQL migration/permission tests. Synthetic browser acceptance covers separate settings dialogs, narrow layouts and delayed reads. Exact-source CI, image and deployment results are recorded separately in [verification](../VERIFICATION.md).

Real provider accounts, billing, network availability, external MCP and cross-session/capacity acceptance remain separate. This release does not create real provider configurations, paid requests, schedules or MCP connections. GitHub Pages stays a synthetic offline demo without a real backend.
