# CoFlow 0.4.0 — AI delivery assistant

- Query project progress, prepare task creation/scheduling and draft linked delivery briefs using the existing Go services. Interactive business writes require explicit confirmation, revision checks and stable operation IDs.
- Configure encrypted personal or team AI services in Settings. Chat Completions and Responses adapters support DeepSeek, GLM, OpenAI/Codex and compatible endpoints, with SSE text, cancellation and request recovery. No subscription or provider credit is supplied.
- Full-page chat has a left history list plus direct template, scheduled-task and MCP entries. The right dock remains available inside modules. Private history supports search, pagination, rename, archive/trash recovery, activity and provider-reported usage.
- Built-in and personal/team task templates have immutable versions and parameters. Scheduled work pins its configuration and template, defaults to read-only/drafts, requires a separate publishing grant, and records runs with leases, retries, change detection and time-zone/DST handling. Calendar shows plans separately from published progress.
- Remote read-only MCP Client supports verified HTTPS connections and explicit tool approval. Changed manifests require reapproval. No local stdio processes, OAuth flow, external write tools or public CoFlow MCP Server.

## Upgrade

Skill remains **1.3.0**. Migrations 012 and 013 are additive and applied by Go at startup. Configure a stable private `COFLOW_AI_ENCRYPTION_KEY` (base64-encoded 32 bytes) before saving model/MCP credentials; keep it with private operational backups. Losing or changing it makes existing encrypted keys unreadable. Never publish credentials or use real services in the offline Pages demo.

Back up the database and private environment, verify both image digests, then replace API/Web only. Existing Todo, Timeline and Calendar remain authoritative. Deployment does not create provider configurations, schedules or reports.

## Validation and limits

63 local JavaScript tests, TypeScript, isolated PostgreSQL/Go tests and assistant race/SSE checks passed during development, with team/demo webpack builds and synthetic browser acceptance. Release-commit CI, image publication and deployments are verified separately in the [verification log](../VERIFICATION.md). Real provider accounts, model-specific compatibility, external MCP services, production load and remaining roadmap capabilities require separate acceptance.
