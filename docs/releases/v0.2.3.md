# CoFlow 0.2.3 · Credential clarity and Skill 1.2.0

## Changes / 变化

- Credentials display actual module scopes and offer an optional form shortcut for task/report integration. Read-only or intentionally limited credentials are not labelled obsolete. Configuration does not automatically issue, expand or revoke credentials.
- Installation prompts declare scopes and provide explicit, opt-in consent for replacing the exact local credential. Existing session authorization is reused. Installation does not create business records or recommend automation by default.
- **Skill 1.2.0** creates a new report for material progress on a later reporting day, even in the same session, linking the same Todo. Retries, corrections and task-link repairs retain the original report identity. Time zones and legacy checkpoints are handled explicitly; a date change alone does not generate a report.
- Single-target setup remains the default. Multiple reporting destinations are an explicitly chosen private project preference, with separate identities, IDs and checkpoints per target.

凭证页按实际权限说明能力，联动权限可从表单配置，不按年龄或前缀误判“旧版本”，不自动签发、扩权或撤销。安装提示词支持明确的本机替换授权，复用会话确认，保持仅安装的范围。

Skill 1.2.0 修正跨天进展被持续写入旧简报、无法进入当日日报的问题：有新进展则新建简报并复用任务；重试、旧内容补正和任务关联修复仍用原标识。无变化不空报，安装后不默认推荐定时任务。单空间是通用默认，多目标只按用户明确选择保存在私有项目配置中。

## Upgrade and validation / 升级与验证

No new database migration or business API is added; migration 010 remains current. Update the Skill entry and all three references together, retaining credentials, task/report IDs and project bindings. Schema-1 single-target bindings remain supported. Existing reports are not split or backdated automatically.

无新增迁移或业务接口。Skill 整套更新至 1.2.0，保留凭证、项目关联及任务／简报映射。旧单目标配置继续兼容；不自动拆分、补发或回填历史简报。

Agent Prompt and localization checks, type checking, documentation/version checks and isolated production builds cover the local changes. Synthetic browser verification covers permission profiles, form preselection and replacement consent. A real Agent session spanning midnight remains a separate pilot scenario. See [verification](../VERIFICATION.md) for CI and deployment evidence as it becomes available.

Release, image publication, private deployment and public Pages are verified independently. Public Pages contains synthetic data only. Release attachments contain public source archives only.
