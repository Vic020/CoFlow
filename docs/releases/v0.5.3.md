# CoFlow 0.5.3 — Conversations visible from the start

## Changes

- Conversations are created before their first model request, so they appear in the private list while the reply is still running. Failed or cancelled first turns retain the original input for manual retry. Results and action drafts still commit atomically; creation alone does not execute a model or business action.
- The sidebar is named **All conversations**. Existing search, active/archive/trash filters and pagination remain. Unanswered input is private to its member/team, never automatically resumed, and retries reuse the same conversation/request identity. Archived or deleted sessions cannot be revived through the creation endpoint; configuration snapshots remain enforced before the first reply.
- Template project, domain and member fields use existing catalog options and match the current page scope. The UI displays names and submits project/member IDs or domain names. Other parameters remain text inputs; required selections guard startup. Scheduled-task parameters share the controls without creating or enabling schedules.
- **Use and start conversation** starts a fresh conversation with the selected template version and current parameters, without requiring another Send click. It does not inherit the previous conversation's web/MCP selections; business writes retain their confirmation cards.
- The session-only API adds `POST /assistant/conversations` for private, idempotent header creation. Conversation detail exposes unanswered first input and parameters to its owner. The unified Agent Skill and token scopes are unchanged.

## Upgrade and validation

Application **0.5.3**; unified Skill remains **1.5.0**. No SQL migration is added; the total remains **16**. Back up and preserve existing database volumes, private environment and encryption master key. Unanswered input is stored in the existing conversation JSON document, separate from a completed turn; this is not a durable background worker or automatic retry queue.

Local checks include 94 JavaScript tests, TypeScript/localization/document/version checks, Go assistant race tests and isolated PostgreSQL integration tests for early visibility, member isolation, replay, failures, archive restrictions and configuration-change races. Existing history/templates, chat retry, streaming completion and Context save regressions passed. Browser acceptance uses intercepted synthetic creation/model responses to verify catalog selection, parameter IDs, one-click startup and visibility before the reply. No real model calls or production business writes were made for this change. Exact-source CI and remote deployment results are recorded separately in [verification](../VERIFICATION.md).

Pages remains an independent offline demo with synthetic data. Other providers, external MCP/Coding Agent compatibility and capacity remain separately scoped acceptance work.
