# CoFlow 0.1.1

首次初始化改为私密链接入口，并将版本发布与部署明确分开。

## 本次变化

- 通过 `https://coflow.example.com/?token=<初始化 token>` 进入初始化，不再提供 token 输入框。
- Go 先校验 token，缺失、错误或已失效时不展示表单；创建时再次校验，数据库保证并发及重启后也只能初始化一次。
- 初始化 token 从服务器 `COFLOW_BOOTSTRAP_TOKEN` 配置读取。未配置或不足 32 位时默认关闭初始化；既有团队正常登录不受影响。
- 网页读取后移除地址栏参数，token 只留在当前组件内存，并设置 `Referrer-Policy: no-referrer`。完整初始化链接应私下保管，访问日志需脱敏查询参数。
- GitHub Pages 提供合成团队数据的独立离线演示，复用 Timeline 与筛选，试填数据刷新后清除；不连接真实团队 API 或数据库。
- 默认先本地测试；Release、Pages 发布和自用服务器部署分别需要维护者明确要求。Pages 工作流改为手动触发，本次仅发布源码版本。

## 使用与升级

首次部署者请参考 [部署指南](https://github.com/Vic020/CoFlow/blob/v0.1.1/docs/DEPLOYMENT.md) 配置 token，并使用完整私密链接初始化。初始化入口仅支持 URL 查询参数，不提供 token 输入框。已有数据库的实例无需重新初始化。

升级需要维护者另行安排；发布本 Release 不更新任何运行中的服务或演示站。本次只交付源码和 GitHub 自动生成的源码压缩包，不上传镜像、真实账号、数据库、凭证或本机验收产物。

## 验证

本地类型、生产构建、版本一致性、Agent Prompt、演示隔离及 Go／PostgreSQL 隔离测试；初始化接口覆盖缺失配置、错误 token、预校验、并发创建与重启后不可重用。网页验收覆盖正确、缺失、错误 URL 参数与无 token 输入框。
