# CoFlow 0.2 Todo 功能与实施计划

更新：2026-10-29（Asia/Shanghai）。状态：A–E 已完成实现与隔离验收，归入 0.2.0。当前版本为 0.2.3，验证范围与实际 Agent／容量限制见 [验证记录](VERIFICATION.md)。

版本范围以 [ROADMAP](ROADMAP.md) 为准，本文细化 0.2 的行为和实施验收。开发期间将实际用户变化记录到 CHANGELOG 的 Unreleased；接口与 Agent 能力实现时同步到 [OpenAPI](openapi.yaml) 和规范 Skill，不提前把规划写成可用协议。

## 目标与范围

Todo 承载多人、多 Agent 共同交付的敏捷流程，看板是当前流程视图。任务明确目标、责任与结果，Timeline 记录每次推进与交付。基本闭环是：明确交付目标并分工 → 成员及其 Agent 在授权范围内推进 → 上报并关联成果 → 反馈与验收 → 确认完成。

后续交互细节以能否促进协作交付为依据：谁负责、当前进展或阻塞是什么、成果在哪里、由谁确认完成。阶段变化表达实际工作进度，不将拖动卡片视为工作完成；已有能力与后续设计分别记录，不把当前四列当作完整敏捷系统。

首版每个团队共享一套看板，通过项目、领域、负责人和快捷范围筛选。支持自定义列、任务编辑与排序、归档恢复、评论与提醒、历史、简报关联、协作转交，以及 Agent 管理。

不包含多看板、子任务、依赖、工时、重复任务、自动执行和外部通知。开始日期、具体时刻与时间范围留给 0.3；0.2 保留可扩展的日期和历史模型，不提前实现日历。

## 看板与任务规则

- 默认列为待办、进行中、待确认、已完成。网页管理员可新增、改名、排序、归档和恢复共享列；至少保留一个有效的未完成列和一个完成列。
- 每列有完成属性，任务完成状态由所在列决定，不再维护独立且可能冲突的状态字段。修改列的完成属性必须展示受影响数量，并在事务中记录任务完成状态变化与历史。
- 任务只属于一列。必填标题与列；可选 Markdown 描述、一名负责人、一个项目、多个领域、优先级、截止日期、交付链接与关联简报。优先级为无、低、中、高，默认无；链接沿用简报最多 20 个的规则。
- 截止日期使用经过 Go 校验的 YYYY-MM-DD 字符串，保存在 PostgreSQL JSONB，不转换成午夜 UTC；按个人展示时区的当天判断逾期，已完成或归档任务不标逾期。
- 移入完成列记录完成时间；移回未完成列清除当前完成时间，保留所有历史完成与重开事件。完成动作默认移入看板指定的完成列，可另选完成列；重开优先返回上一个有效未完成列，否则选择目标列。
- 不内置单独的阻塞状态，团队可建阻塞列，原因保留在描述、评论与简报。
- 归档独立于完成，任务归档后退出默认视图，可在归档入口恢复。首版不提供永久删除。
- 归档含任务的列时，必须将其全部任务（包括归档任务）迁入有效目标列，保留原有相对顺序并追加到目标列尾部；列归档和迁移同事务完成。目标完成属性改变时一并更新完成记录。
- 负责人必须是当前团队有效成员；成员离队保留历史署名，当前负责人标记已离队，允许有权成员重新分配，不向离队成员通知。
- 分类合并更新任务引用并保留历史；已归档分类可展示和筛选旧任务，但不能新选。Agent 不自动创建未知分类。

## 页面与交互

侧边栏新增 Todo，与 Timeline 并列。页头沿用标题、搜索和新建，下方紧凑筛选栏，不增加重复概览卡片或顶部横条。卡片突出标题，次级显示负责人、优先级、项目／领域和截止日期。

任务详情以居中弹窗默认阅读，双击或点击铅笔逐字段编辑；上部放主要字段，中部放描述、交付链接和关联简报，下部用讨论／历史页签区分沟通与操作记录。任务评论讨论安排与验收，简报评论讨论本次成果，互相回链且不自动复制。任务分享链接可直接打开详情，仍校验当前团队访问权限。

| 范围 | 定义 |
| --- | --- |
| 全部 | 当前团队未归档任务 |
| 与我相关 | 我创建、负责、评论或被提醒的未归档任务 |
| 待我处理 | 我负责且未完成、未归档的任务 |

搜索与项目、领域、负责人可组合；重置清除搜索、筛选和快捷范围。桌面支持跨列拖拽、列内排序、列排序，同时提供键盘和菜单操作。手机横向浏览列，通过菜单移动、置顶或置底，详情使用适配视口的居中弹窗，可纵向滚动。筛选视图必须显示筛选结果数量，避免误解为列总量。

## Timeline 联动

### 上报入口与双向引用

- Todo 详情提供上报进展，打开现有上报弹窗并关联当前任务，预填项目与领域；这些是初始值，后续修改简报分类不反向修改任务。
- Timeline 上报弹窗提供可选关联任务，优先显示当前项目未归档任务；支持搜索和多选。一个任务关联多次上报，一条简报可关联多个任务。
- 已有简报详情提供关联已有任务和创建任务。创建时预填标题与分类，用户确认负责人和列，任务保留来源简报；界面显示已有任务引用，创建使用幂等标识。
- Timeline 卡片显示任务名称与当前状态，点击打开任务；Todo 详情按时间展示关联简报并回到原文。关联不复制简报正文、评论或链接快照。
- Agent 上报增加可选 todo_ids，逐一验证团队与读取权限。每次独立进展使用新 source_id；修正同一次简报复用原 source_id。Todo 与简报各有自己的 source_id，不混用。

### 可选任务移动与联合提交

默认上报只写简报与引用，不改变任务状态。选择任务后，可显式为每个任务选择目标列；简报已交付不等于任务已验收，不能按简报状态批量推断任务完成。

联合提交携带简报幂等标识、任务目标列和每个任务预期修订号，Go 在一个事务中校验权限、修订、引用并写入简报、任务、历史和通知。任一项失败全部回滚；冲突返回 409，网页保留草稿供重新读取处理。重试必须识别已成功的同一次请求，不重复创建、移动或通知；已提交后再次修改任务必须使用新的操作标识和修订号。顺序由服务端根据目标列当前顺序追加，并更新排序修订。

Agent 关联任务需要 reports:write 和 todos:read；联合移动另需 todos:write 与对象维护权限。修改已有简报关联沿用简报编辑权限，并校验任务读取权限；关联不能授予维护任务的权限。只允许引用读取者可见的对象；简报软删除后隐藏其内容并显示不可用引用，恢复后重新可见。归档任务保留历史引用并标明归档；移除成员或撤销权限后不能通过旧链接或引用读取受限内容。

### 现有协作请求转交

- 关联已有任务只增加引用，不修改原协作状态。
- 显式转为任务后，一条协作请求最多对应一个接管任务；重复操作打开已有任务。
- 原协作保留原始状态和讨论，显示由 Todo 跟进及当前任务状态，停止独立状态更新，退出旧待处理统计。后续操作在 Todo 完成，不保留两套可写状态。
- 转交要求原协作的维护权限与任务创建权限；转交、来源关联、历史和通知同事务提交，不批量迁移历史协作。
- 已转交任务归档前，如仍未完成，明确提示归档会移出待处理；保留任务恢复入口，不恢复旧协作的独立状态维护。

### 通知与日报

任务新分配、重新分配、评论提醒、完成和重开进入站内通知；普通排序与文字编辑只记历史。沿用现有轮询机制，通知可直接打开任务。联合提交对同一接收人合并重复通知，提供简报和任务入口，不向操作者自己发送重复提醒。

日报继续基于当天实际简报，不把拖拽变成简报。新增的任务完成数单列展示，按展示时区、事件发生日和任务 ID 去重，不重复计入简报交付数；重试与重复完成不重复计数。完整跨周期趋势与统计口径在 0.6 实施。

## 数据与权限

| 对象 | 内容与约束 |
| --- | --- |
| 看板 | 每团队唯一、默认完成列、排序修订号；已有团队首次初始化与新团队创建均须幂等 |
| 列 | 稳定 ID、团队、名称、完成属性、顺序、归档时间与修订号 |
| Todo | 稳定 ID、团队、业务字段、列与顺序、创建人、负责人、完成／归档时间与修订号 |
| 来源与关联 | 创建来源、简报多对多引用、协作接管唯一关系、幂等请求记录 |
| 评论与事件历史 | 实际操作者、Agent／Model 来源、对象修订、字段前后值、事件时间和操作标识 |

历史记录稳定列 ID、当时完成属性及分类／负责人变化，为 0.6 按事件统计提供依据；列改名、归档、重开和分类调整不能丢失事件语义。API 来源字段只记录来源，不作为权限主体；团队和操作成员由认证上下文确定。

| 动作 | 普通网页成员 | 网页管理员 | Agent |
| --- | --- | --- | --- |
| 读取任务、列和必要元数据 | 当前团队 | 当前团队 | todos:read |
| 新建任务 | 允许 | 允许 | todos:write，并具备 todos:read |
| 编辑、移动、归档、恢复 | 创建人或负责人 | 团队内全部 | todos:write + todos:read，且为创建人或负责人 |
| 发表评论和提醒 | 当前团队 | 当前团队 | todos:read + comments:write |
| 管理共享列 | 不允许 | 允许 | 不允许，包括管理员 Token |

已有 Token 不自动扩权，新增 Todo 权限需由用户明确授予。todos:read 可读取操作所需的成员、项目与领域元数据，不附赠简报读取权限；关联简报内容仍要求 reports:read。成员自己的评论管理沿用作者／网页管理员软删除恢复规则，Agent 不获得删除恢复评论的能力。

## API 与一致性

以下接口已在本地源码实现，字段、权限与响应以 OpenAPI 为准。

| 接口组 | 计划操作 |
| --- | --- |
| /api/v1/todo-board | 读取列、默认完成列与排序修订 |
| /api/v1/todo-columns | 网页管理员创建、更新、排序、归档迁移与恢复 |
| /api/v1/todos | 筛选与分页查询、幂等创建 |
| /api/v1/todos/:id | 详情、按修订更新、移动、归档恢复 |
| /api/v1/todos/:id | PATCH action=comment/delete-comment/restore-comment；GET 内含讨论与变更历史 |
| /api/v1/todo-completions | 日报使用的完成事件与当时分类，按本地日期和任务 ID 去重 |
| 现有 reports 与 collaborations | 扩展引用、联合提交与协作转交 |

- 创建唯一来源为（团队、成员、source_id）；重复创建返回已有对象，不隐式覆盖人工改动；同操作标识不同请求内容返回冲突。
- 内容修改、移动与生命周期操作携带任务修订；列设置携带列修订。过期返回 409，不按最后一次提交覆盖。
- 拖拽提交目标列、相邻任务 ID、任务修订及看板排序修订，由 Go 计算顺序并在事务中更新。筛选后只改变被移动任务的位置，其余任务相对顺序不变；无可见锚点时追加列尾。
- 先采用看板级排序修订与行锁保证正确性；列内顺序使用可重排的数值位置，必要时事务内重编号，避免依赖客户端整列覆盖。
- 看板查询支持跨列或指定列分页，前端跨列读取全部页；数量和分页使用相同筛选条件，提供稳定游标；不能将一次返回的局部列表当成完整列来重排。
- Next.js 负责界面和同源转发；业务与授权在 Go，持久化在 PostgreSQL。新增迁移，不修改已应用迁移。
- 现有通知绑定简报，需要扩展 Todo 对象引用和权限过滤；分类合并、成员移除、简报删除恢复、日报与协作统计一并纳入集成测试。
- 统一使用 skills/coflow/SKILL.md，通过 references/todos.md 加载任务规则，复用现有私有凭证配置与安装机制；网页 Prompt 先读稳定 ID 再操作，不包含密钥。规范与公开下载副本由 scripts/sync-agent-assets.mjs 同步。
- 团队模式、本地 demo 和 Pages 各自实现适配。演示只使用合成数据，Pages 无真实后端，不连接真实账号或 API。

## 验收场景

仅使用两个隔离团队、两名合成成员和模拟 Agent；实际 Agent 跨会话能力需另外按环境记录，不把 API 模拟当成真实 Agent 验收。

1. 人创建和分配任务，Agent 在授权下推进并关联多次上报，负责人验收、完成、重开。
2. 一条简报关联多个任务，详情双向跳转；引用不复制内容，软删除、恢复与权限撤销正确。
3. 联合上报权限不足或修订冲突时全部回滚；草稿保留，成功重试不重复创建、移动、事件或通知。
4. 人与 Agent 并发编辑不静默覆盖；同 source_id 不重复创建，同操作标识不同载荷被拒绝。
5. 筛选／分页后移动、并发拖拽、列归档迁移、完成属性变更正确；刷新与换设备保持顺序。
6. 协作转交幂等，旧状态不再独立维护，待处理和通知不重复；旧协作讨论与来源保留。
7. 跨团队对象 ID、无权成员、旧 Token 和管理员 Agent 的越权写入全部拒绝；成员退出后不再收取通知。
8. 逾期日期、完成事件与日报按个人展示时区正确处理；重复完成不重复计数，历史事件足以支撑后续统计。
9. 桌面、键盘、手机、中英文和独立演示可完成核心流程；Pages 无真实 API 请求。

运行相称检查：Go 单元／race 与隔离 PostgreSQL 集成测试、前端类型与生产构建、Agent Prompt、i18n、demo、docs:check、version:check。未配置测试数据库而跳过的测试必须标为未验证。

迁移 010 使用每团队唯一的 todo_boards JSONB 文档保存列、任务、讨论、事件和幂等结果，复用团队事务锁；通知和协作来源继续使用关系表。只读操作在文档未变化时不重写。首版沿用小团队现有事务和回滚边界，尚未声明大规模看板容量。后续按任务量和历史增长评估拆分任务、事件和幂等表，不改变稳定 ID 与 API 语义。

本地 Go demo 的 Todo 在独立进程内存中，服务重启后重置；既有演示简报仍遵循原本的本机存储。Pages Todo 只保存在页面模块内存，刷新重置且无后端。两种演示均与 PostgreSQL 团队数据隔离。
