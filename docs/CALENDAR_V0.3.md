# CoFlow 0.3 Calendar 功能与实施计划

更新：2026-11-01（Asia/Shanghai）。状态：纳入 0.3.0 发布，Skill 1.3.0 新增 Calendar 参考文件；线上能力以已部署版本为准，发布与部署结果见验证记录。

版本范围见 [路线图](ROADMAP.md)，现有任务基线见 [Todo 实施计划](TODO_V0.2.md)，现行接口与 Agent 规则仍以 [OpenAPI](openapi.yaml) 和 [CoFlow Skill](../skills/coflow/SKILL.md) 为准。实施时才将已验证的接口与规则同步到规范源文件。

## 目标与最小闭环

Calendar 是已有工作在时间上的共同入口，连接计划、实际进展与交付。Todo 保存持续工作、责任和状态，Timeline 保存每次进展及证据；Calendar 投影已有记录，并管理尚无来源对象的阶段和节点，不再复制另一套任务或简报。

首个可验收闭环为：打开上报日历 → 看哪些日期有上报 → 点日期查看当天简报与交付 → 打开原简报及关联 Todo → 回到原日期和筛选。随后扩展：为已有 Todo 排期 → 在排期日历中查看／改期 → Todo 同步 → 关联真实进展，比较计划节点与实际交付。

不包含外部日历双向同步、重复事件、复杂依赖、资源自动调度、完整 Sprint 系统、工时／绩效统计或自动启动其他 Agent。

## 页面与默认上报视图

0.3.1 周历拖选：在空白时间列按住鼠标拖动，实时查看蓝色时段与起止时间，松开后进入节点弹窗；以半小时为单位覆盖选择范围，反向拖选同样有效。Esc 清除选区；键盘可用上下方向键选择、Shift 扩选、Enter 确认。普通触屏滚动保留，创建仍需弹窗保存，进度简报不受影响。

0.3.1 快捷创建：双击月历空白日期、周历日期／全天区或小时网格可创建节点，默认带入对应全天日期或半小时时段；首次进入显示一次性提示，关闭或刷新后不重复，普通新建按钮继续可用。甘特左侧底部点“+”展开一条新建行，在右侧按住拖选日期、松开进入弹窗；也可用左右方向键移动、Shift 扩选、Enter 创建、Escape 清除选区。范围包含首尾日期，反向拖选自动整理；取消不写入，保存后才建立实际节点。周历按展示时区预填，夏令时重复／不存在的时间要求明确选择。进度视图创建的是计划节点，可在排期查看，不产生简报。

0.3.1 交互优化：简报在日历内的居中弹窗阅读、评论和编辑，复用 Timeline 详情。月历、周历、当日列表及节点关联均保留原日期和筛选；支持当前上下文的直接链接和返回关闭，详情即时读取。

侧栏新增 Calendar，沿用现有页头、搜索、紧凑筛选和居中阅读详情的设计。首访且 URL 未明确指定模式时，默认进入**进度月历**（英文 Reports）。一级入口为进度、排期、甘特；前两者提供月／周切换，甘特直接呈现同一份排期数据。

| 模式 | 默认内容 | 布局与主要动作 |
| --- | --- | --- |
| 进度（默认） | 真实 Timeline 简报的日期分布与当天成果 | 月／周；选日、读简报、进入关联任务、从任务发起上报 |
| 排期 | 已排期 Todo、截止节点、项目阶段、Big Day、版本节点 | 月／周；查看、安排、改期和关联成果 |
| 甘特 | 与排期共用任务、节点及筛选 | 范围条；按项目／领域分组、比较计划范围 |

周视图采用七天小时网格：全天排期和截止节点放在顶部，具体时间显示时间块，简报只标真实创建时刻、不代表工时；支持重叠排列、跨午夜和夏令时。桌面右上角小月历可切月、选日／选周，并显示周数、今天和当前选择；手机通过日期定位并在周网格内滚动。切换入口和日期保留全局工作范围。旧的上报及甘特链接继续兼容。

- 日期工具包含今天、前后翻页、月份／周定位和明确的展示时区。上报模式不提供拖动简报日期；甘特仅用于排期。
- 日期格展示经过筛选的简报数量，空间足够时展示少量标题；点、数量与文字一起使用，不能只依赖颜色判断有无上报。超出显示容量时有“更多”入口，不能截断实际记录或漏掉分页。
- 点日期在日历旁展开当天列表，手机在日历下展开；列表突出标题、作者、状态、时间、交付链接及关联任务数量。点条目复用现有居中简报详情，可继续阅读正文、讨论、历史和交付链接。
- 有上报、无上报、加载中、读取失败和无权限使用不同呈现。无上报只是该日期在当前筛选下没有简报，不解释为没有工作、没有交付或成员未履职。
- 手机优先紧凑月历＋选日日程，小时周历在容器内横向浏览，操作不依赖 hover；提供键盘日期移动、选择、焦点与可读名称。甘特可横向浏览，日期也可在详情直接编辑。
- URL 保存模式、布局、日期、时区与允许的筛选；从 Todo／节点进入时显式定位排期或关联对象，不能被默认上报模式覆盖。关闭详情、浏览器前后退与从来源对象返回，恢复原日期和筛选。链接只定位，不授予访问权限，也不静默切换团队。

## 上报日期、筛选与计数

上报月历与 Timeline 日报使用同一规则：按简报 **created_at** 在展示时区中的日期分组。updated_at 表示修订时间，不能让旧简报自动跑到今天；不从标题、source_id 日期或任务截止日期猜测上报时间。

- 使用账号已保存的展示时区，演示偏好仍为浏览器本地。查询按该时区的日／周／月边界转换成 UTC 半开区间；按真实时区规则处理夏令时、跨月、跨年和跨午夜，不能固定按 24 小时切割。
- 默认仅显示当前可访问且未删除的简报，删除／恢复遵循原模块规则。修订不增条数；一条简报关联多个 Todo 或领域，日期总数仍按 report ID 去重。
- 项目、领域、作者、简报状态、Agent／Model 来源、关键词使用现有语义与权限。上报模式的“成员”指作者；排期模式指任务／节点负责人，标签明确区分，不把作者当成任务负责人。
- 简报按自身分类筛选，不因关联 Todo 分类变化而自动改写。任务／节点详情可以查看其获准读取的关联简报；若这些简报不属于当前日期或筛选，明确标注“历史关联／筛选外关联”，不把它们计入当天数量。
- 日历日期数量、当天分页列表和跳转后的 Timeline 使用相同条件。仅有关联交付链接的数量，不宣称链接代表已经验证的交付；任务完成数、排期节点数和简报数分开呈现，不合成“总产出”。
- 沿用 Skill 1.2.0：同一 session 跨上报日期有新进展则新简报、复用原 Todo；纠错、重试或补关联仍更新旧简报，无变化不空报。Calendar 不自动拆分、补发、复制或回填历史简报。

## 与现有模块的双向联动

| 来源／动作 | Calendar 中的表现 | 原模块中的联动与边界 |
| --- | --- | --- |
| Timeline 新增、编辑、删除／恢复简报 | 对应日期、列表和计数重新读取 | 同一 report ID；保留原评论、历史及权限，不复制“日历简报” |
| 点简报中的任务 | 打开原 Todo 详情，可再定位其排期 | 同一 Todo ID；原简报和日期上下文保留 |
| Todo 新增／改期 | 更新该任务的时间条和截止节点 | 使用同一任务写入及修订检查，看板详情同步，无需两边各存一份 |
| Todo 完成、重开、归档／恢复 | 保留计划时间，更新状态及可见性 | 不自动补报、改期或制造完成证据；完成历史仍在 Todo |
| 从排期任务发起上报 | 复用现有上报弹窗，预选当前任务 | 简报按真实上报时间进入上报日历；不默认完成任务 |
| 项目阶段、Big Day、版本节点 | 展示计划范围／目标日及关联成果 | 关联现有项目和 Todo／简报，点击回原记录；无上报显示暂无关联，不推断延期 |
| 原评论、协作与通知 | 回到其所属简报／任务及允许的上下文 | 不新建重复讨论；事件提醒仅在确有协作动作且获授权时发送 |

在任务／节点详情区分“当前日期的上报”和“全部关联进展”。一张任务可跨多天关联多条简报，一条简报也可关联多项任务；使用真实多对多关系，不仅靠名称或项目相同猜测关联。历史成果关联到未来节点时，展示真实上报日期，不移动它来匹配计划。

阶段／节点可显式关联 Todo 和简报。仅因 Todo 同时属于某版本，不自动把所有相关简报标为该版本的交付；展示时说明直接关联或经任务关联的来源，并按 report ID 去重。交付、完成、验收仍沿用现有 authority 和状态规则。

## 排期对象与时间模型

| 对象 | 计划时间 | 说明 |
| --- | --- | --- |
| Todo | 可选完整时间范围；原有 due_date 独立保留 | Calendar 与看板维护同一任务，项目／领域和单一负责人沿用原模型 |
| 项目阶段 | 一段日期或具体时刻范围 | 表示项目周期，必须能查看其关联任务与进展 |
| Big Day | 全天日期或具体时刻节点 | 上线日、发布会、交付日等，可关联任务与成果 |
| 版本安排 | 目标日期／时刻节点 | 团队业务计划，不修改仓库 VERSION，不自动发版、打标签或部署 |

- Todo 的可选 schedule 对象分为 date-range（日期型）和 time-range（具体时刻型），避免与已有 due_date 混用。字段及迁移已写入 OpenAPI；既有无 schedule 任务保持原行为。
- 日期型 start_date／end_date 按界面展示两端包含，校验起始不晚于结束；查询使用日期区间 `[开始日, 结束日次日)`，全天日期和 due_date 不因个人展示时区切换而移动到另一天。具体时刻 start_at／end_at 以 UTC 保存并记录 IANA 排期时区，要求结束晚于开始，查询使用半开区间；不把全天日期先转成午夜 UTC 存储。
- 完整范围要成对填写，不虚构缺失的持续时长。仅有 due_date 的旧任务展示独立截止节点，不猜测开始时间；无排期无截止的任务进入“待排期”。
- 计划结束与截止日期是不同字段。改期不能静默改截止日期，完成任务不能静默改计划；计划晚于截止日期时提示风险，保留明确选择，不改写历史。
- 拖动、范围拉伸与详情编辑经过 Go 校验及修订检查；冲突时保留草稿并重新读取，不覆盖别人刚改的时间。节点可用详情中的日期字段完成同等操作，手机与键盘不依赖拖拽。
- 甘特首版按项目／领域分组，展示计划范围、节点及当前状态，可打开关联进展；不把上报时间当作任务实际用时，也不自动生成无依据的“实际甘特”。

## 实现方案与权限

保持 Next.js + Go + PostgreSQL。业务身份、可见性、筛选、分组、去重、日期查询、幂等和修订校验在 Go，前端只负责布局、交互与展示，不用前端聚合绕过权限。

### 读取与模型

- 上报日历是现有 reports 的只读投影，按查询区间读取，不新增简报副本或按日聚合业务表。增加可选范围、时区、分页及按日计数能力，保持旧调用方兼容；范围与列表的过滤共用服务逻辑。
- Todo schedule 先扩展现有任务文档与历史；独立阶段／节点建议使用关系表及关联表保存团队、类型、时间、负责人、修订与来源引用。服务事务与现有团队锁保持一致，并定义统一加锁顺序，避免跨模块写入死锁。
- 日历读模型使用带来源类型的稳定引用区分 report、Todo 排期、Todo 截止和独立事件；前端投影标识不当成新的业务对象 ID。每个来源只在其所属模块维护。
- 需要组合查询时由 Go 返回范围、时区、来源能力和各类结果；来源未授权／失败不能伪装成 0，也不能泄露其数量。列表和计数采用一致查询快照或修订标识，翻页因并发修改不一致时可明确刷新。
- 先用隔离合成数据验证查询计划与索引，再按实际查询增加索引。月份／周范围有上限、明细有分页，不先下载整个团队所有历史记录后在浏览器筛选。

### 模块权限

| 数据／操作 | 权限边界 |
| --- | --- |
| 查看上报日期、计数及简报 | 现有 reports:read；仅凭它应能使用默认上报视图，不额外要求排期写权限 |
| 上报／编辑进展 | 现有 reports:write 与对象规则；关联任务另需 todos:read，联合移动另需 todos:write |
| 查看 Todo 排期／截止 | 现有 todos:read，不附赠读取简报内容的权限 |
| 维护 Todo 排期 | 现有 todos:read/write 与创建人／负责人规则；网页沿用现有管理权限 |
| 查看／维护独立阶段与节点 | 新增 calendar:read/write；本地实现已可签发，写入仍检查对象权限，线上须等待部署 |
| 评论、成员提醒及协作 | 复用原模块读取／评论权限和用户授权，不因进入 Calendar 获得新权限 |

跨来源操作分别检查权限。旧凭证不自动扩权；报告型凭证可先使用上报日历，只有任务权限的凭证不能从关联数量或摘要间接读取简报。拟新增事件的 Agent 写入限创建人／明确负责人，网页管理员按现有团队规则维护；事件关联也不授予其引用内容的访问权。

范围查询、事件及关联维护 API 已同步到 docs/openapi.yaml、隔离权限测试及统一 Skill 的 Calendar 参考文档。部署前不把本地新增接口描述为线上已可用；旧实例返回不支持时停止对应操作。不提供 CLI、MCP 或自动调度能力。

### 前端、加载与缓存

- Calendar 进入默认上报模式只请求必要元数据、当前范围计数与列表（月历按选日分页，周历有界加载本周全部分页），不预加载整个 Todo 看板和所有排期事件；切到排期再按权限和当前范围加载对应来源。
- 显式维护加载／失败／无权限状态，快速切换日期、模式、时区或团队时丢弃旧响应，避免串团队或显示错月数据。
- 延续浏览器内存短缓存和请求去重，缓存键包含身份、团队、角色、来源、范围、时区和筛选；私有 API 继续 no-store，不默认引入服务器共享业务缓存。
- 上报／修订／删除恢复、任务写入／改期、事件修改后统一失效相关日历读缓存，并保留跨标签页失效。时区变化重新查询和分组，不能复用不匹配的日期桶。
- 复用现有简报／任务详情与上报弹窗，补定位参数；不复制一套编辑状态、评论和验收流程。所有新增界面使用中英文消息目录，保留用户撰写内容原文。

## 可执行工作包与顺序

以下保留实施分包与验收标准；当前本地实现进度见下方记录，不将规划本身视为验收完成。

| 包 | 实现内容 | 完成依据 |
| --- | --- | --- |
| A 基础契约 | 来源投影、时间／时区、范围过滤、计数／分页、权限矩阵、Todo schedule 与事件迁移草案 | 可手算样本及契约评审；不破坏旧 reports／Todo 调用 |
| B 默认上报日历 | 月／周、日期标记／数量、当天列表、筛选和原简报／Todo 回链 | reports:read 单独可用；数量与列表、日报一致；手机／键盘可用 |
| C Todo 排期闭环 | 开始结束范围、原 due_date 截止节点、待排期、详情编辑与月／周改期 | Calendar 与 Todo 同一记录；刷新持久化；冲突与权限正确 |
| D 阶段与里程碑 | 项目阶段、Big Day、版本节点及显式关联 | 可回查任务和进展，计划与实际日期不混用，跨团队访问拒绝 |
| E 甘特与 Agent | 分组范围条、节点、拖动／拉伸、Agent 读取与获授权改期 | 手机详情替代操作可用；幂等、修订、审计与规范同步 |
| F 联合验收 | 合成演示、旧数据迁移、中英、缓存失效、跨日／时区和真实 Agent 试用 | 实际验收记录、明确未验证项，按授权另行发布和部署 |

建议先完成 A＋B 作为首个验收节点：不用先建一堆排期对象，即可利用现有上报查看团队发生了什么。最终 0.3 范围仍包含 C–F，不因中间验收自动改版本或发版。

## 使用与实现说明

1. 从侧栏打开 Calendar，默认进入上报月历；查看每天的数量和标题，选日读取当天列表，进入原简报继续讨论、查看关联任务与交付。无需 Agent 额外关联日历。筛选、日期、时区及模式保存在 URL，浏览器返回可恢复上下文。
2. 切换“排期”查看 Todo 与阶段／节点；月／周适合定位日期，甘特适合比较计划范围。只有截止日期的任务保留截止节点，不猜测工期；未排期列表仅包含既无排期也无截止日期的任务。
3. 点任务先阅读，再点铅笔修改排期；也可以在原 Todo 详情双击“排期”或点击铅笔编辑。全天日期两端包含；具体时间记录 IANA 排期时区与 UTC 时刻，结束时刻不包含。夏令时重叠必须选定时刻，缺失时间不能静默顺延。
4. 全天范围可拖动到日期格；甘特尾部把手可调整结束日期。具体时刻通过详情编辑，避免拖一天意外改变时区或工期。手机和键盘均可使用日期字段。改期不改截止日期、完成状态或既有上报；超过截止日期时提示风险。
5. “新建节点”建立项目阶段、Big Day 或业务版本节点，按需选择负责人、分类、关联任务和近期上报。节点阅读详情保留原成果链接与历史；归档后可通过原事件 URL（`?event=ID`）或浏览器历史重新打开并恢复。归档不是删除来源任务或简报。
6. Agent 使用同一 CoFlow Skill 的 [Calendar 参考文件](../skills/coflow/references/calendar.md)。Todo 排期沿用原任务权限；独立节点新增 calendar:read/write，须明确签发，新权限不加到旧凭证。先验证当前服务接口确实可用，旧服务不支持时不能用重复上报替代。

### 迁移与缓存

- `011_calendar.sql` 增加独立事件、幂等操作记录与日期索引；现有 Todo JSON 文档增加可空 schedule，旧任务不回填、不改日期或状态。API 启动沿用带校验和的事务迁移机制，部署前仍需按部署流程备份。
- 真实上报通过 PostgreSQL 范围索引查询；按日计数、最多三条标题预览与当日分页共用 repeatable-read 快照。排期读取与跨模块写入使用相同团队事务锁，再按修订分页。Todo 仍沿用现有团队 JSON 文档存储；超大团队的关系化迁移／容量基准未在本次完成，不能宣称无限容量。
- 浏览器仅缓存列表 10 秒并合并相同请求，键含身份及完整范围／时区／筛选；写入、会话变化和跨标签通知失效。详情不缓存，切回窗口重新读取。私有 HTTP 保持 no-store，不是服务器共享业务缓存。
- 默认上报页只读取元数据及范围查询；进入原 Timeline 详情时仍使用原模块加载逻辑，不把原模块的全部历史加载描述成已一并重构。
