# CoFlow 统一界面与异步反馈规范

适用于 Timeline、Todo、Calendar、AI 助手、设置，以及后续新增模块。目标：**信息直接可读，操作位置稳定，加载不打断当前工作。** 业务内容与权限仍由模块／Go 决定，本规范不新增缓存、身份或执行授权。

## 布局与层级

- 页面沿用“导航 → 工作范围 → 标题／操作 → 局部筛选 → 内容”。同一页面的标题、说明、筛选、按钮不得因请求开始／结束而上下移动。
- 全局项目／领域／成员筛选使用现有统一入口，不在模块内重复同一含义的控件。初次等待元数据时预留同高区域，不等数据回来再插入一排控件。
- 一个区域保留一个主操作；次要操作使用轻按钮，低频操作收进菜单。异步进度靠近触发位置或区域右上角，不占用整行。
- 信息层级使用现有字号、颜色及字重；正文优先 13–14px，辅助信息 11–12px，图标 14–16px。标题不与辅助说明争夺注意力。
- 优先使用现有设计变量和组件，间距以 4／8／12／16／24px 为基准；不为每个页面另造一套边框、阴影、圆角或状态颜色。

## 加载状态：强制要求

| 场景 | 必须做到 | 禁止 |
| --- | --- | --- |
| 首次进入，无同作用域数据 | 先稳定标题、操作栏、筛选及内容容器；内容位置显示与列表／列／日历相符的骨架 | 只放一个不明显的旋转图标；插入“加载中”顶行；整个页面蒙白 |
| 同作用域刷新／轮询 | 保留最近一次成功内容、可用控制和滚动位置；固定槽位显示细进度条 | 把有效内容重新换成骨架、清空列表、让空态闪一下再回来 |
| 切换筛选／日期 | 尽量复用该上下文快照；新结果未完成前明确忙碌状态，不把旧结果当成已刷新结果 | 反复回原、用过时请求覆盖新范围 |
| 新团队／账户／权限范围 | 丢弃不属于新身份的旧内容；显示稳定的首屏容器并重新校验权限 | 为了“保留内容”展示另一个团队或账号的数据 |
| 按钮提交／验证／保存 | 仅当前操作按钮反馈和防重，保持宽高、文字不换行，原位置显示结果 | 额外增加一行 spinner；全屏禁用所有无关导航 |
| 失败 | 保留仍有效的原内容；在相关位置显示可理解的错误和一个恢复动作 | 用错误抹掉原列表；失败后把空结果说成“暂无数据” |
| 成功／复制 | 在按钮原位置短暂反馈；结果有实质变化时再更新内容 | 在页面顶端追加提示行，推动整个页面 |

### 固定槽位与时序

1. 首次读取使用 [`ContentSkeleton`／`PageLoading`](../apps/web/components/ui/loading-status.tsx)，按列表、动态卡片、Todo 列、月历、周时间网格、甘特或设置选择结构。骨架只包含装饰块，不显示虚构正文／数量或伪操作；不能替换刷新中仍有效的内容。
2. 刷新使用同文件的 `LoadingStatus` 固定细进度条，显隐只改变 `visibility`，不改变槽位尺寸；小于约 **150ms** 的请求不闪动画，结束立即收起。首屏以骨架为主，不叠加旋转图标。骨架只做轻微呼吸动画，减少动态效果模式下静止显示。
3. 同一操作只保留一个主要指示，不同时出现顶行“加载中”、按钮转圈、蒙层及 toast。禁止让一个 SVG 作为 flex／grid 的独立占行子项。
4. 并发请求使用计数或明确请求身份；一个请求先结束不能把另一个请求的状态清掉。切换上下文后的旧响应不得覆盖当前内容；组件卸载后不继续改当前状态。
5. 加载期间空态不提前展示。只有首次请求完成且未失败后，才展示“暂无数据”。已有列表不为同作用域刷新反复清空。
6. 缓存与样式分别处理：缓存可减少等待，不能替代稳定布局；即使缓存未命中或网络慢，也必须符合本规范。现有读取缓存仍按成员／团队隔离和失效，不因视觉优化放宽权限。

## 控件、弹层与反馈

- 文字按钮 `white-space: nowrap`，按内容决定宽度并防止 flex 压成竖排；长名称和模型名截断，完整含义用辅助说明或可访问名称提供。
- 下拉、菜单和弹窗复用现有组件；点击外部／Esc 收起，选择成功后关闭。菜单浮层不改变内容布局，也不把实现细节作为默认产品说明。
- 阅读默认是 view，编辑有明确入口；异步加载不自动进入编辑、不改变用户当前输入或选中对象。
- 验证／保存区使用明确状态：未验证、验证中、已验证、失败。完成状态不继续提供会重复计费或重复写入的无意义操作。
- 普通操作不加全屏遮罩；确需阻断的安全确认、身份校验或不可并行流程另按现有权限规则处理，不为减少跳动省略必要确认。
- 动画只用于状态变化，不动画化布局高度、页面透明度或内容位置；尊重 `prefers-reduced-motion`。保留键盘焦点，状态使用本地化可访问说明，错误用 `role="alert"`，区域按需使用 `aria-busy`。

## 验收清单

- 用缓存命中／短请求及约 800–1500ms 延迟分别检查；不能只看快速本机网络。
- 在加载前、加载中、完成后测量标题、说明、操作栏及筛选的 `getBoundingClientRect()`：**同一状态切换的位置／尺寸差应为 0（至多 1px 测量误差）**。首次新增真实数据的内容填充不应推动顶栏。
- MCP／模板／定时／历史切换的内容区先显示骨架，不出现临时顶行，不显示“暂无”再立刻出现真实内容。确认刷新进度条始终占固定槽位。
- Todo／Timeline 刷新时原数据仍在；Calendar 日期刷新保留视图结构及固定刷新按钮。分页、失败重试和重复点击也要检查。
- 检查桌面、窄屏、长英文按钮、中文和减少动态效果模式；不得横向溢出或把按钮文字挤成竖排。
- 页面可切换和按钮可操作，不代表已保存／已执行；完成提示必须来自成功响应。只用合成数据做截图及自动化验收。

当前落地：工作空间首载、Timeline／Todo／Calendar／设置以及助手管理列表使用结构骨架；已加载内容刷新使用固定进度条，空态等待读取完成，保留标题、说明和操作位置。后续新增、修改异步界面按此规范逐项验收，不将这份要求描述为所有旧页面已经完成专项检查。
