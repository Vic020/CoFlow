# 文档与 GitHub 维护流程

仓库为准，GitHub 各入口按职责同步。默认先本地开发、检查与验收；公开同步不代表发布或部署。

## 职责与依据

| 位置 | 内容与依据 | 更新条件 |
| --- | --- | --- |
| README 中英版 | 产品故事、现有功能、快速开始与路线图摘要 | 能力、启动方式或版本展示变化 |
| `docs/` | 使用、开发、运维与规划的详细源文档 | 与相关代码同一次提交 |
| Wiki 中英版 | 面向用户的精简指南，技术细节链接到 docs | 用户操作、限制或对应源文档变化 |
| Projects | 事项、目标版本、进度及 Issue／PR 链接 | 计划确认、实施进度或验收结果变化 |
| Release | `docs/releases/vX.Y.Z.md` 的公开发布说明 | 明确要求发布且目标提交通过验证 |

功能事实以源码与实际验收为准；接口以 `docs/openapi.yaml`、Agent 行为以 `skills/coflow-report/SKILL.md` 为准；版本范围以 `docs/ROADMAP.md` 为准。Wiki 和 Projects 不独立制定功能、权限或版本承诺。发现不一致时先修正源文件，再同步摘要。

README 默认英文，同时提供中文翻译；Wiki 以英文页面为默认入口，提供 `-zh-CN` 对应页面。正文可按受众精简，但操作步骤、限制和功能状态保持一致，语言切换链接可用。其他详细文档当前以中文维护，通过文档索引提供入口。

## Wiki 映射

[docs/wiki-map.json](wiki-map.json) 记录每个公开页面的英文／中文 slug 及仓库源文件。新增、改名或删除页面时一并更新映射与 Wiki 侧栏、语言链接；保留原 URL 或提供迁移入口，避免旧链接失效。

现有页面覆盖 Home、Quick-Start、Agent-Reporting、Team-Collaboration、Personal-Settings、FAQ、Roadmap。同步时：

1. 根据源文件改动确认受影响的页面，不复制整份开发或运维文档到 Wiki。
2. 同步英文和中文正文，检查页内链接、语言切换、`_Sidebar` 和 `_Footer`。
3. 公共 Wiki 只使用合成身份、示例域名和公开链接；不粘贴真实安装提示词、凭证、邀请链接或私有运维清单。
4. 在有公开同步授权时更新 Wiki，读取发布后的页面确认结果；只有本地 Wiki 文件改动时记录为“待同步”。

映射是同步索引，不代表远端内容已经更新；本地检查不会访问或修改 GitHub。

## Projects 状态

| 状态 | 进入条件 |
| --- | --- |
| 待规划 / Backlog | 需求尚未定范围，不承诺版本 |
| 待开发 / Ready | 目标、范围和验收标准已明确 |
| 进行中 / In progress | 已开始实施，关联 Issue／PR |
| 待验收 / In review | 实现可检查，仍有验证或评审未完成 |
| 已完成 / Done | 验收通过，交付提交和验证结果可追溯 |

通过验收才标为完成，不能因为创建 PR、合并代码或发布 Release 批量标完成。通过验收但未发布可以是 Done；是否发布通过目标版本、关联 Release 和交付说明区分，不增加含义重复的状态列。

事项记录标题、简短目标、验收标准、目标版本（未确定则留空）、关联 Issue／PR。版本调整先更新 ROADMAP，再同步 Projects。完成时记录实际验证和交付引用；取消或重复事项说明原因并关闭，不伪装为已完成。看板状态按这些语义使用，现有字段的变更需在获准维护 Projects 时核对后实施。

## 每次变更清单

1. 完成本地实现与相称的隔离验证，检查隐私和拟提交内容。
2. 更新受影响的 docs、README 中英版、规范及 CHANGELOG 的 Unreleased。Skill／OpenAPI 下载副本由同步脚本生成，不独立修改。
3. 运行 `npm run docs:check`、`npm run version:check`；涉及界面文案时运行 `npm run test:i18n`，其余测试按改动范围安排。
4. 提交／推送按用户授权执行；同时列出受影响的 Wiki 页面与 Projects 事项，在获准范围内同步并核对结果。没有权限、未获公开同步授权或远端失败时记录“待同步”，不宣称完成。
5. 交付说明分别报告仓库、Wiki、Projects、Release、部署的结果；无相关变化写“不适用”，只有本地更改写“本地完成／待推送”。

公开同步授权包含用户要求更新 Wiki／Projects 的请求；普通本地修改、提交、推送不自动授权新增公开事项、改动整个看板或发布 Release。已经明确授权的工作继续完成，不重复确认。

## 发版与部署

依照[版本管理](VERSIONING.md)整理版本、发布说明和验证范围。明确要求创建 Release 后，从目标已推送提交打标签，发布对应说明，核对版本、提交和公开附件；历史说明保留当时事实。变更后的新文档不能被描述为已经包含在旧标签内。

Release、[Pages 发布](GITHUB_PAGES.md)、[真实团队部署](DEPLOYMENT.md)各自需要明确指令，不能因其中一项完成而触发另一项。私有服务器、备份和验收记录不写入 GitHub。

## 手动镜像构建

[GitHub 镜像工作流](IMAGE_BUILDS.md)仅从 main 上已通过 CI 的稳定标签构建通用镜像，不接入生产 Secrets，不使用自用服务器作为 Runner。记录源提交、运行和摘要，分别报告构建、GHCR 可见性、匿名拉取与部署的状态；不能用构建成功代替部署验收。

## 自动检查的边界

`npm run docs:check` 只检查本地文件目标（Markdown 内联及 HTML 链接，不校验页内锚点或外链）、README 中英入口、Wiki 映射源文件与页面标识；版本由 `version:check` 检查，界面翻译由 `test:i18n` 检查。CI 执行这些只读检查，不发布内容、不改状态、不递增版本。

语义翻译是否准确、文档与功能是否一致、Wiki 远端内容、Projects 实际状态、部署结果仍需人工或有授权的 Agent 核对，不能从 CI 通过推断。
