# 协作闭环：增量反馈、接续与任务推进

状态：0.4.1 起随源码发布，应用 0.4.3、Skill 1.4.0；实例是否部署以验证记录为准。以实际 `/meta.agent_capabilities` 判断服务是否提供新入口，不能仅凭版本或下载的新文档假设线上已可用。

## 外部 Coding Agent 接续

先用现有私有项目绑定核验 health 和 meta 的团队／成员、实际模块权限，再明确当前项目／任务及用户委托。

1. 首次使用 `GET /api/v1/agent/changes?project=<id>`，取得空基线和 `next_cursor`。
2. 调用 `GET /api/v1/agent/context?project=<id>` 或 `?todo=<id>`，读取原任务、近期反馈与证据、尚待处理的协作、相关独立日历节点。必要时从原模块补读与分页。
3. 按原游标读取 changes，直到 `has_more=false`。只返回对象类型、ID、时间与链接；相同对象可能出现多次，按 ID 合并后重新读取最新对象。
4. 成功处理这一页后再保存 `next_cursor`。游标作为最小私有检查点，按服务、团队、成员、项目隔离；失败不前移，不在绑定里保存反馈正文或聊天。
5. 在授权内推进，回读结果，再按统一 Skill 维护 Todo 和有意义的进展简报。反馈、分配或变化事件本身不授予新的执行权限，也不代表另一个 Agent 已开始工作。

先建立基线再读上下文，可以在下一轮增量中接到读取期间发生的变化；可能重读，不能用“摘要已经看过”跳过原记录。新会话复用同范围游标和稳定任务，不能重新创建同一工作。

`changes-v1` 和 `context-v1` 不存在时，继续使用原有 Todo／Timeline／Calendar／协作接口读取，不探测写权限、不扩大凭证、不反复请求不存在的接口。持续轮询、外部提醒和定时任务需要用户的相应委托；本功能不创建后台监控。

## 数据和权限

- 迁移 014 开始记录紧凑失效事件，不回填历史正文。事务回滚不留下事件；读取与写入共用团队锁，避免游标越过未提交的事件。
- Todo 的创建／修改／评论、简报及讨论／协作变化、独立日历节点变化进入流；共享列改名等管理变化仍通过重新读取元数据获得。项目改归属同时让原项目与新项目看到失效信号。
- 按模块读取权限过滤。身份、项目或模块读取权限变化时旧游标失效，重新建立基线并完整接续。未提供某模块权限时，context 在 `omitted_scopes` 中列出，不能解释为“没有任务／反馈”。
- 事件只要求重读原对象，不是完整审计历史；删除或失去访问权后不恢复旧正文，不改变网页未读状态。
- context 返回最多 10 项任务、5 条简报、10 项未转交的未结束协作及 10 个独立节点；每项任务／简报最多 3 条近期评论，正文摘录最多 600 字节并标明省略。保留原 ID 与来源接口、总数及截断提示；详情和完整证据回到原模块读取。
- context 是按权限进行的多次读取，不承诺同一事务快照，不自动推断决策、验收或下一步，不替代 0.5 Context 知识库。

## 内置 AI 助手推进任务

新增“接续协作”和“推进任务”两个内置模板，原模板版本保留。模型可使用 `read_handoff`、`read_changes` 读事实，使用 `propose_task_change` 准备单项变更：

| 操作 | 确认卡与执行 |
| --- | --- |
| 移动／完成／重开 | 显示原列与目标列；读取任务及看板修订，确认后复用原 Todo 服务 |
| 转派 | 使用当前团队已核验的成员 ID，显示负责人；不启动或通知外部 Agent 执行 |
| 评论 | 预览正文，确认后写原任务讨论；不隐式添加 @ 提醒 |

没有确认不写入；人工改动后的旧草稿拒绝执行，重新读取后准备新草稿。业务已提交但响应丢失时复用动作 ID 重放，不再次发表评论或移动。原模块保留操作者、服务端设置的助手来源和修订历史。

完成需要实际验收依据或用户明确的完成授权；简报“已交付”不自动代表任务通过验收。后台定时任务仍只读／简报草稿，不能使用新任务推进工具写入。
